> 目标：让 aimy 自己的 pnpm workspace 能安装 AIRI Core Agent 的必要依赖，并运行上游 Core Agent 单元测试；不实现桌面 UI 或真实模型链路。

## 1. 本阶段目标与非目标

### 目标

- 在 `digital-lover/packages/` 内保留 AIRI Core Agent 及其传递 workspace 依赖，保持可审查的源码副本。
- 保留 Core Agent 上游测试，并提供 aimy workspace 内可复现的测试命令。
- 让 aimy 执行 `pnpm install` 成功；建立来源、版本、许可与同步规则。
- 不影响已存在的 companion、memory、relationship、avatar-fitting 包。

### 非目标

- 不复制 `stage-ui-three`、`stage-shared`、DuckDB、Electron 应用或完整 AIRI monorepo；它们不属于 Core Agent 测试闭包，等 M1/M2/M4 确认实际消费边界后再接入。
- 不调用任何真实模型、不要求 API Key、不将 mock 测试描述成模型验证。
- 不改 `/Users/mima1234/Documents/aimy/airi-main`。
- 不在本阶段启动 M1 功能实现或创建 aimy 桌面应用。

## 2. 架构裁决

采用 **选择性源码 vendoring + workspace 包边界**：

```text
digital-lover (pnpm workspace)
├── packages/core-agent                 # AIRI Agent runtime 与原始单测
├── packages/provider-inference          # provider 适配
├── packages/plugin-protocol             # 插件/事件协议
├── packages/server-sdk                  # 客户端协议依赖
├── packages/server-shared               # SDK 共享类型
├── packages/stream-kit                  # 流处理
├── packages/pipelines-audio             # Core Agent 依赖的音频管线接口
├── packages/audio                       # pipelines-audio 的传递依赖
└── packages/better-ws                   # server-sdk 的传递依赖
```

包之间沿用 AIRI 的 `@proj-airi/*` 名称和 `workspace:` 关系，不搬入 AIRI 根目录的整个 catalog、patches、hooks、turbo/Vite 配置。第三方依赖由 aimy 的 lockfile 固定；AIRI catalog 别名在导入的 package manifest 中解析成对应版本范围。

此边界与现有 PRD 一致：新增产品域模块仍留在 `@digital-lover/*`；AIRI 包作为独立能力底座，不把业务逻辑塞入上游包。

## 3. 依赖闭包与纳入理由

从当前 AIRI `packages/core-agent/package.json` 的 production/workspace 依赖递归核查，闭包为 9 个包：

| 包 | 纳入理由 | 本阶段执行验证 |
|---|---|---|
| `core-agent` | 本阶段主要复用目标，含 21 个测试文件 | 原始 Vitest 测试全量运行 |
| `provider-inference` | Core Agent 的 provider 归一化依赖 | 安装、typecheck/build 所需依赖；不单独扩大集成范围 |
| `plugin-protocol` | Core Agent 协议依赖 | 安装与依赖构建 |
| `server-sdk` | Core Agent 频道 SDK 依赖 | 安装与依赖构建 |
| `server-shared` | `server-sdk`/Core Agent 共享类型 | 安装与依赖构建 |
| `stream-kit` | Core Agent FIFO/流处理依赖 | 安装与依赖构建 |
| `pipelines-audio` | Core Agent 音频 pipeline 依赖 | 安装与依赖构建 |
| `audio` | `pipelines-audio` 的 AIRI workspace 依赖 | 安装与依赖构建 |
| `better-ws` | `server-sdk` 的 AIRI workspace 依赖 | 安装与依赖构建 |

依赖图应以实际 package manifest 复核；新增任何 AIRI workspace 依赖都必须补入闭包或证明该入口不需要。stage/VRM/UI 与数据库包暂不纳入是有意的按需延后，不代表永久裁剪。

## 4. 包来源、版本与升级策略

- 来源记录：仓库 `moeru-ai/airi`，本地参考目录 `../airi-main`；参考快照日期为 2026-09-23。该参考目录当前 Git 没有任何 commit（`HEAD` 不存在），因此无法记录可复现的 commit SHA；包版本以各导入 package manifest 记录为准。原仓库许可证副本放在 `packages/airi-upstream-LICENSE`。
- 保留各导入包原有 package 名、版本、源码、测试和必要构建配置；排除 `node_modules`、生成的 `dist`、覆盖率和缓存。
- 导入范围内的 `catalog:` 依赖统一解析为 AIRI 当前 catalog 声明的版本范围；带命名 catalog（例如 Vitest catalog）也按原定义解析。导入包自身的 `workspace:` 依赖继续指向已纳入的 AIRI 包。
- 不自动追随 AIRI 上游。升级时先比较源码、manifest、测试和许可证差异，重复安装与测试验收后再更新记录。
- 只允许 aimy 专属的最小 manifest 改动（例如给 `core-agent` 暴露测试脚本）；记录在同步说明中，不能静默改写上游运行逻辑。

## 5. pnpm 安装脚本策略

T0.3 必须通过当前 pnpm 版本的依赖构建审批闸门。处理原则：

1. 先从实际安装错误识别被阻止的包及生命周期脚本，禁止为了让安装通过而无差别批准全部依赖。
2. 只将经审阅、确实需要且适用于 aimy 当前平台的依赖脚本设为允许；不需要的安装脚本设为拒绝或保持默认拒绝。
3. 记录脚本用途与影响；不得执行未知下载/编译脚本而不检查其行为。
4. 重跑安装后检查 pnpm 配置和 lockfile diff，确保没有生成占位值、未审阅依赖或非预期更新。

本地检查发现失败涉及 `protobufjs`、`sharp`、`onnxruntime-node`。执行时逐项检查当前 pnpm 的 blocked build 列表、安装脚本行为和本机平台用途；只审批实际需要的 `protobufjs`/`sharp`，让 `onnxruntime-node` 保持拒绝。若 pnpm 当前版本不能表达逐包拒绝且只允许审批所需脚本，则升级/替换 pnpm 配置前先停下，不得扩大审批范围。

## 6. 测试与构建策略

### 基线证据

- AIRI 当前根 Vitest 配置的 Core Agent 项目已在只读源库运行：**21 个测试文件、147 项测试通过**。
- 使用方式是 AIRI 根配置的 `pnpm exec vitest run --project @proj-airi/core-agent`。`packages/core-agent` 自身配置若作为独立 config 从仓库根执行，会因相对 include 路径不匹配而报告没有测试；aimy 脚本必须从包工作目录按该包配置执行。
- Core Agent `package.json` 本身没有 test script，所以 aimy 增加显式脚本属于 workspace 接线，不改测试实现。

### T0.3 验收命令

1. `pnpm install`：从 aimy 根执行，退出码 0。
2. 对闭包包执行必要 build/typecheck，确认 workspace 导入和 package exports 正常。
3. `pnpm --filter @proj-airi/core-agent test`：21 个文件、147 项通过。
4. `pnpm --filter @digital-lover/relationship-engine test` 与 `typecheck`：原有 8 项测试继续通过。
5. 查看 git diff、lockfile 与忽略规则，确认没有密钥、生成物、AIRI 源目录更改或 sibling 目录更改。

### 不在本阶段的验收

- 真实模型文字对话、延迟测量、桌面 Electron 窗口和语音/屏幕权限均属于后续阶段；没有 Key 时只在相应阶段标“待验”。

## 7. 失败与回滚边界

- 安装失败：保留错误证据，不标记 T0.3 完成；优先检查 workspace 依赖声明、包管理器审批和锁文件，不删除现有数字恋人包。
- 测试少于/多于基线：比较测试发现范围与失败，不通过删测试/缩窄 include 来伪造通过。
- 兼容问题需要升级 pnpm、Node、替换包管理器或大范围改 AIRI 架构时，停止并先提交影响说明给产品经理确认。
- 回滚只移除本次新建的 AIRI 副本及本次新增的锁文件/配置差异；不重置父仓库 index，不删除原有暂存文件。
