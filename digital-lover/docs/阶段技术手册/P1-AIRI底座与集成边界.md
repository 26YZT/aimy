# P1 技术手册：A 工程基线与 AIRI 集成边界

> 承接已批准 A 阶段。九包已接入，不重复导入；当前真实状态与验证见 PROJECT_STATE。

## 目标

让独立工作区依赖与运行入口完整，错误不泄露凭证；明确后续桌面、UI、VRM、音频、视觉和存储的实际消费边界。

## A 阶段任务

1. 检查完整工作区 package/类型/测试依赖，补缺失 Node/Vite 类型与 Vitest 声明；全包类型检查和相关测试可运行。
2. 固定 CLI 独立运行入口，验证无配置正确退出、模拟流式成功、取消/失败清晰；真实模型无条件时如实待验。
3. 在 provider 调用与日志出口统一异常脱敏；保留假凭证/内部错误回归，不输出真实 Key。
4. 同步 PRD/规则/任务入口，旧验收断言撤销；保存源码和父仓库 Git 暂存基线，不擅自清理或提交原有暂存。
5. 列出正式角色、音色与资源的缺口和授权状态；占位资源不计正式交付。

## 后续集成边界

- 沿 AIRI stage-tamagotchi → stage-ui → core-agent/provider 和 stage-ui-three 实际调用链接入；按 package/catalog/平台脚本核验闭包。
- 角色人格、VRM 和音色配置不含供应商密钥；BYOK 的存储、进程及外部发送边界明确。
- 会话提供多轮、文字/图片、流式、取消和错误；不把 CLI readline 搬成产品界面。
- 屏幕与麦克风独立门禁；关闭终止已有采集并拒绝后续调用。
- 形象信号通过映射驱动；存储为会话、设置、关系和记忆明确读写、恢复、删除与迁移责任。
- 本地 AIRI 会话链路使用 IndexedDB，两个 DuckDB 目录为迁移说明；不得把空目录当已接入数据库。

## 出口

A 范围内全包类型检查及相关测试通过，CLI 可独立运行，异常脱敏回归与可恢复基线有证据。真实模型/桌面/设备未验项分列；A 通过不代表 B～E 完成。

后续新消费包保留来源、许可证和原测试；若必须替换 AIRI 栈或大范围改 API，先给证据与可审阅方案，不以演示掩盖兼容成本。
