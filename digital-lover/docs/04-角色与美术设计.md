# 04 · 角色与美术设计

> 承接 [PRD-MVP-重构版.md](PRD-MVP-重构版.md)。一期一个官方 VRM 角色；用户自建/导入与多角色后置。正式角色、人设、模型、动画与音色仍需方向及授权验收。

## 1. 角色由三部分构成

| 部分 | 内容 | 验收 |
|---|---|---|
| 人格 | 背景、性格、语气、开场与示例对话 | 多轮一致、适合游戏/视频陪伴 |
| 形象 | VRM、材质、骨骼、表情/口型与动画 | 目标 macOS 的 AIRI 渲染链路实测 |
| 声音 | 合法音色与 provider 配置 | 与人格/形象一致，中文及真实语音链路可用 |

AIRI 角色卡与展示模型分离，可作为适配基础；一期统一提供一套配套角色，不借此扩展用户自建需求。

## 2. 形象表现：资源与程序共同驱动

| 表现 | 模型/资源提供 | 程序负责 |
|---|---|---|
| 表情 | 表情变形/映射 | 情绪选择、强度、平滑切换与冲突处理 |
| 眨眼与视线 | 闭眼变形、眼球/头部绑定 | 时机、追踪、待机微动；一期无摄像头 |
| 口型 | aa/ee/ih/oh/ou 等可用口型 | 根据实际音频驱动与同步、播放取消后收口 |
| 待机与动作 | 兼容骨骼、待机/手势动画 | 调度、混合、状态切换与中断 |
| 语气 | 音色能力与模型输出 | 口语表达、TTS 参数适配、与情绪/动作协调 |

AIRI 有相关驱动作为参考，不能仅凭表情数或动画文件断言“像真人”。是否自然由真实音频、资源质量、调度和产品体验共同验证。

## 3. 官方资源要求

- 一个官方角色包含可识别人格、可用 VRM、至少一种待机动作、基础表情与口型、配套合法音色。
- VRM humanoid、表情与口型必须在实际渲染中检查，不能保证任意模型导入即用。
- 保存模型、贴图、动画、字体、图标和音色的来源、许可、修改/再分发限制与署名要求。
- AIRI 示例模型与音色不自动获得 Aimy 产品许可；演示占位明确标注，不计为正式资产。
- 不未经许可克隆真人声音，不因替换品牌而删除上游许可与致谢。

## 4. 交付与未决项

A/B 同期准备角色概念、桌面占位、说话/情绪样机、声音参考与资产清单，交产品负责人评审；C/D 前补正式资源并实测。第一角色人设/画风、动作风格、声音与界面方向尚未确定，不再询问已确定的角色数量和桌面优先级。

`avatar-fitting` 只保留后置接口；不能保证任意导入模型通过补映射就与官方模型同样自然。
