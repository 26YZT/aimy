# 03 · Aimy 二开方向索引

> 产品需求与已批准决策只维护在 [PRD-MVP-重构版.md](PRD-MVP-重构版.md)，当前进度看 PROJECT_STATE，任务顺序看任务编排。本文提供实现分类，不另立需求总纲。

## 1. 已对齐的方向

Aimy 是有形象、声音、人格和记忆的虚拟情感陪伴角色，优先陪用户打游戏、看视频。支持文字、用户分享图片、可打断连续语音和授权看屏。情感陪伴可以发展亲密关系，阶段/好感数字为辅助机制。

macOS 优先、一个官方 VRM、本地优先、无摄像头；少量受邀用户 BYOK；一期不做露骨内容。游戏内操作/独立游戏、云同步、订阅、自建角色与电脑自动操作后置。

## 2. 二开内容分类

| 分类 | 重点 | 实现原则 |
|---|---|---|
| 复用与适配 | AIRI 桌面、会话、provider、音频、视觉、VRM | 沿真实消费闭包小步接入；参考库只读 |
| 体验增强 | 插话、回声、屏幕及时回应、表现协调 | 先做 B 实验，测量后再进入 D 集成 |
| 产品规则 | 主动陪伴、连续人格/情绪/关系、记忆 | 领域模块与薄适配；确定性代码管边界与存储 |
| 产品呈现与资源 | 一个官方角色、合法音色、入口与设置 | 早期样机评审，资源与程序共同决定表现 |
| 试用硬化 | 配置、权限、取消、恢复、降级、安装、反馈 | 自动化、真实链路、人工验收分别记录 |

## 3. 当前执行顺序

A 工程基线 → B 关键体验验证 → C 桌面文字/图片多轮切片 → D 实时语音/看屏/表现/隐私 → E 连续陪伴/记忆/受邀试用。

界面和资产方向在 A/B 同期准备可审阅材料，不等到所有能力完成才套壳；正式角色和声音验收仍独立于代码测试。既有 P 手册按任务编排映射使用，旧 M 路线不继续作为执行顺序。

第一角色人设和画风、VRM/动画的合法来源、声音风格与合法音色、界面视觉、主动陪伴默认频率仍待评。先形成样机与资产清单；不重复询问已确定的角色数量、桌面/游戏优先级或商业模式。

已有 relationship-engine 保留作为领域原型；companion/memory 的接口占位不是交付能力。后续不预建全部未来 schema、不用空目录充当数据库或产品模块已完成。
