# Aimy MVP 产品需求总纲

> 状态：产品负责人于 2026-10-07 批准产品方向与 A–E 开发路线。本文是唯一产品需求总纲；文件名沿用以保持已有链接。批准需求不等于功能、资产或 MVP 已验收，当前事实见 [PROJECT_STATE.md](PROJECT_STATE.md)。

## 1. 产品定义

**Aimy 是虚拟情感陪伴产品，让用户感到一个有形象、声音、人格和记忆的角色，正与自己共同经历日常。** 桌面角色是当前呈现方式；基于 AIRI 二次开发，加强拟人感、实时陪伴、多模态交流与及时反馈。

用户首先在打游戏、看视频时得到相关回应，也可以直接分享文字、语音与图片。情感陪伴可以发展亲密关系；恋爱阶段和好感数值服务于相处体验，不作为产品中心或唯一成功指标。

### 产品原则

1. 先验证关键体验，再扩大代码量；用户尽早看到可评价的角色与界面。
2. 复用 AIRI 的 Agent、provider、音频、VRM、桌面与会话能力，产品规则通过领域模块和薄适配层接入。
3. 按纵向切片交付；接口占位、参考源码与运行中的产品能力分别记录。
4. 模型生成语言和建议，确定性代码维护权限、关系值、持久化与安全边界。
5. 本地优先、可恢复；本地存储不代表模型推理不向外部服务发送内容。

## 2. 用户、场景与边界

第一版面向少量受邀用户，由用户配置自己的模型服务（BYOK）。目标用户希望与有声音、形象和连续人格的角色长期相处；该需求来自产品愿景，尚不能当作独立用户研究或留存证据。

### 核心旅程

1. 启动、配置模型服务并看到一个官方角色，缺少资源或配置时有可理解提示。
2. 多轮文字交流、分享图片、获得流式回复；可取消生成和恢复会话。
3. 授权麦克风后连续交谈，用户插话能停止旧语音并接续新输入。
4. 授权屏幕后理解游戏或视频画面，及时给出相关反应；语音、口型、表情和动作协调。
5. 设置主动陪伴频率或安静模式；安静时不主动打扰，仍可被用户主动唤起。
6. 独立关闭看屏或麦克风，采集与后续调用真正停止，状态明确。
7. 重启后保持会话与已确认记忆；用户可查看、纠正和删除记忆。

### 默认与后置范围

- 默认 macOS 优先、一个官方 VRM 角色、本地优先、无摄像头。
- 一期不做露骨内容；落实未成年人基础保护与危机/自伤兜底。
- 游戏/视频**陪伴**进入一期；进入游戏操作、独立游戏世界后置。
- 订阅、支付、账号体系、云同步、多端、自建角色/任意 VRM 导入及电脑自动操作后置。
- 不一次支持大量模型、音色或平台；按聊天、ASR、TTS、视觉能力分别验证用户配置。

## 3. MVP 功能与验收

| ID | 能力 | 可验证结果 |
|---|---|---|
| MVP-01 | 启动与角色配置 | 一个官方角色的人格、形象和声音配套；资源缺失可诊断 |
| MVP-02 | 文字与图片对话 | 多轮流式、图片理解、取消生成；错误可恢复；取消后的旧输出不混入新一轮 |
| MVP-03 | 桌面角色与表现 | VRM 待机、说话和基础表情；窗口可拖动/隐藏/重开；隐藏/关闭停止相关采集；设置可恢复 |
| MVP-04 | 连续语音与插话 | VAD/ASR/LLM/TTS 链路工作；角色说话时仍能识别用户插话，停止旧播放并接住新输入 |
| MVP-05 | 授权看屏 | 能对测试游戏/视频画面作出相关回应；记录采样、理解和输出耗时及可能漏掉的事件 |
| MVP-06 | 隐私控制 | 屏幕/麦克风独立授权、默认关闭；拒绝不循环弹窗；关闭/隐藏/退出后停止 stream 并拒绝新调用 |
| MVP-07 | 主动陪伴 | 安静模式零主动发言；频率和冷却有效；触发/沉默原因可观察，避免重复打扰 |
| MVP-08 | 人格、情绪与关系 | 跨轮保持人格；情绪有原因、可恢复；声音、表情、动作协调；关系事件经代码校验 |
| MVP-09 | 会话与记忆连续性 | 会话、关系和已确认记忆跨重启恢复；检索相关、纠正生效、删除后不再召回 |
| MVP-10 | 安全、降级与交付 | 不泄露凭证/堆栈；网络及单服务故障可理解降级；安装、配置、清数据和反馈路径清晰 |

桌面对话切片先实现 MVP-01～03 的基础链路；其余能力按 D/E 接入。切片可用不等于完整 MVP 已完成。

## 4. 技术架构与接口边界

| 层 | 路线 | 边界 |
|---|---|---|
| 桌面 | Electron + AIRI stage-tamagotchi | 主进程维护窗口、系统授权、采集生命周期与受限 IPC |
| 界面与形象 | Vue 3 / TypeScript、stage-ui、stage-ui-three / VRM | 复用实际消费闭包；UI 状态与业务权限一致；不开放任意 Node 能力 |
| Agent 与模型 | core-agent、provider-inference | 保留流式/取消/hook/context；不在 Aimy 内再绑定独立厂商 SDK |
| 音频 | pipelines-audio、audio 与 provider | 同时处理输入、播放、打断、回声及旧请求取消，按设备实测 |
| 屏幕 | AIRI 捕获与 vision workload | 授权后按需要采帧；摘要只作为观察数据，不作为工具指令 |
| 产品规则 | relationship-engine、companion-engine、memory 与薄适配层 | 保留已有原型，按当前功能接入，不先创建所有未来领域包 |
| 本地数据 | 以 AIRI 当前 IndexedDB 会话链路为起点核验 | 为会话/设置/关系/记忆明确写入责任、迁移和删除，做真实重启恢复 |

本地 `duckdb-wasm` 与 `drizzle-duckdb-wasm` 目录只有迁移说明，不能视为已接入数据库。数据库适配以当前源码和恢复验收为依据；不为了旧文档引入 DuckDB 或云端 pgvector。尚未接入 Aimy 的会话/关系/记忆不能声称已持久化。

### 必要接口能力

- 会话服务接受文字/图片/语音转写，提供多轮上下文、流式输出、取消与错误状态。
- 音频适配能停止播放、取消旧合成、保持或恢复用户输入；使用请求标识隔离陈旧结果。
- 权限层分别判断屏幕与麦克风，调用前复查授权，关闭时终止正在进行的采集。
- 表现层接受经过校验的说话/情绪/动作信号；模型不能指定任意资源路径。
- 存储层支持恢复、纠正与删除；领域对象的具体 schema 在对应切片中沿用/适配实际源码，不提前把全部未来字段定死。

### 模型策略

BYOK 配置聊天、ASR、TTS 和 Vision，分别说明可用能力、外部发送内容与失败表现。开发期已有兼容接口仅为可替换配置，不锁定某一家供应商。真实验证记录回答质量、中文表现、首字/首声时间、流式稳定性及实际调用成本；未测项留空并标待验。

## 5. 数据流、隐私与安全

- 用户输入 → 会话状态与权限检查 → AIRI Agent/provider → 流式文字/语音 → 表现映射 → 会话写入 → 经校验的关系事件与候选记忆。
- 观察 → 隐私门禁 → 安静/冷却/频率判断 → 允许后生成陪伴回应 → 表现与原因记录。模型不能自行打开权限。
- 插话 → 检测有效用户输入 → 停止旧播放/取消旧合成与相关生成 → 新一轮识别/回应；陈旧输出不得恢复播放。
- 关闭采集 → 更新开关 → 主进程终止已有 stream/捕获 → 拒绝新调用 → 界面明示状态；待返回旧结果不得继续触发陪伴回应。

BYOK 凭证不进入仓库、安装包、截图或日志；运行时存储和进程边界需实测，不承诺客户端能隐藏平台密钥。原始截图/音频默认不长期保存；外部模型可能接收请求内容，设置需清楚解释。本地记忆带来源并允许用户纠正、删除；权限、关系值、删除和恢复由确定性代码维护。

## 6. A–E 开发路线

| 阶段 | 交付结果 | 退出条件 | 手册 |
|---|---|---|---|
| A 工程基线 | 工作区依赖完整、CLI 独立启动、异常脱敏、统一需求、可恢复源码基线 | 全包类型检查及相关测试通过，明确真实验证空位 | P0/P1 |
| B 关键体验验证 | 连续语音、插话、回声、流式播放/口型及屏幕反馈实验 | 实测耳机/扬声器表现和耗时，说明可行性及剩余缺口 | B、P2 |
| C 桌面垂直切片 | 启动、一个 VRM、多轮文字/图片、取消、重启恢复 | 用户可完整走通；错误、取消、恢复有效 | P3 |
| D 实时感知与表现 | 连续语音、授权看屏、声音/口型/表情/动作与隐私控制 | 真实设备/真实模型与关闭负例通过 | P4 |
| E 连续陪伴与试用 | 主动陪伴、情绪、关系、记忆、安全降级、安装与试用 | 少量受邀用户完成体验验收，保留反馈与未通过项 | P5/P6 |

现有 P0～P7 文件名保留以稳定链接；当前顺序以 A–E 为准。旧 M0～M8 表保留历史记录，不作为当前执行优先级。美术/声音方向评审与 A/B 并行，正式资产到 C/D 前需要确认。P7 游戏另行立项，不反向扩大当前 MVP。

## 7. 质量与验收记录

### 必须分别记录的证据

- 自动化：安装/构建/类型检查、相关单元/集成测试、模拟 provider 与设备负例。
- 真实链路：目标 macOS、真实模型、麦克风/扬声器、屏幕权限、取消与重启。
- 人工体验：人格一致性、拟人表达、游戏/视频回应相关性与及时性、主动打扰程度。
- 交付与成本：安装/首次配置、资源授权、实际费用和未验证项。

### 测量和场景

- 延迟先建基线再定目标；分别记录 ASR、LLM 首 token、TTS 首帧、插话停止及屏幕事件到回应耗时，不编造“真人级”达标。
- 耳机与扬声器、用户与角色同时说话、环境噪声、设备切换、限流/断网、权限拒绝/关闭均需验收。
- 连续运行 30 分钟记录角色稳定性与内存趋势；会话/关系/记忆用新进程重启并检验恢复、纠正和删除。
- 安静模式零主动发言；关闭看屏后无屏幕来源搭话；TTS 失败保留文字、ASR 失败可打字、视觉失败仍能聊。

| MVP 评审 | 当前判定方式 |
|---|---|
| 角色与声音 | 正式资产获授权，产品负责人认可人格/视觉/声音一致性 |
| 交流与感知 | 用户亲自完成文字、图片、可打断语音与看屏旅程 |
| 隐私与连续性 | 采集关闭有效；重启、纠正、删除实测通过 |
| 稳定与交付 | 目标 macOS 上安装、配置、降级、恢复与反馈可复现 |

需求批准、技术通过、真实链路验证与人工验收分开记录。仅测试全绿不能称为 MVP 完成；评审结果由 PROJECT_STATE 与对应证据维护。

## 8. 决策与待评资产

已批准：虚拟情感陪伴、AIRI 二开、游戏/视频陪伴优先、文字/图片/连续语音/授权看屏、可插话打断、可发展亲密关系、少量受邀用户 BYOK、macOS/一个官方 VRM/本地优先/无摄像头、一期不露骨内容，以及 A–E 顺序。
