## 1. 目标

在不重构 AIRI 的前提下，新增 aimy 自己的命令行文字聊天入口：从本地 `.env` 读取配置，通过 AIRI 的 `provider-inference` 创建模型 Provider，再通过 AIRI `core-agent` 的 `streamFrom` 完成真实流式输出。

本阶段不做 Electron、Vue、VRM、ASR/TTS、屏幕捕获、主动搭话或真实工具执行。

## 2. 架构

```text
stdin
  -> text-chat-cli/config
  -> AIRI provider-inference
  -> AIRI core-agent/streamFrom
  -> stream event adapter
  -> stdout
```

产品新增代码放在 `packages/text-chat-cli`，不修改 AIRI 参考库。AIRI 包只作为只读复用来源，保留其原有测试和补丁。

## 3. 技术选择

- TypeScript + pnpm workspace：与当前 AIRI 底座一致。
- Vitest：沿用 AIRI 测试体系。
- `providerOpenAI`：默认支持 OpenAI Responses API；也允许配置 OpenAI-compatible API。
- `streamFrom`：复用 AIRI 的模型协议、流式事件、AbortSignal 和错误处理，不在 aimy 中另写一套 LLM SDK。
- dotenv：只在 CLI 边界读取 `.env`；API Key 不进入代码、日志、截图或错误消息。

## 4. 配置契约

默认读取：`AIMY_API_KEY`、`AIMY_MODEL`、可选 `AIMY_BASE_URL`、可选 `AIMY_API`。支持显式传入 env 对象，便于测试。缺失必填项立即失败，错误信息不得包含密钥。

## 5. 流程与边界

1. 启动时校验配置。
2. 创建 AIRI Provider。
3. 读取一行用户输入。
4. 通过 `streamFrom` 发送单轮对话。
5. 将 `text-delta` 事件按顺序输出。
6. 失败时输出脱敏错误；支持 AbortSignal。

第一版只验证单轮文字链路，后续再接完整会话编排、持久化和 UI。

## 6. 验收标准

- 配置缺失有明确错误且不泄露 Key。
- 流式 delta 能正确拼接。
- AIRI Core Agent 与 Provider-Inference 原有测试继续通过。
- 新包 test、typecheck 通过。
- 无有效新 Key 时，真实模型验收明确标记为“待验”，不以 mock 冒充。
