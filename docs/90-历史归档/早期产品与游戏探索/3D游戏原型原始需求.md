我要开发一个类似“AI角色真实生活在3D游戏世界中，并能够和玩家自然互动”的游戏原型。  
  
参考目标不是普通 ChatGPT 聊天窗口，也不是传统 NPC 对话树。  
  
核心体验是：  
  
玩家进入一个3D场景后，可以和一个具有独立人格的 AI 角色自然交流。  
  
AI 角色能够：  
  
* 听懂玩家的话  
* 理解当前游戏环境  
* 记住之前发生的事情  
* 根据人格和情绪生成回复  
* 决定自己的行为  
* 做出对应的表情、动作和姿态  
* 主动发起互动  
* 根据玩家的行为改变关系状态  
  
最终玩家应该产生一种感觉：  
  
“这个角色不是游戏里的一个聊天框，而是真的生活在这个世界里。”  
  
⸻  
  
1. 第一阶段目标  
  
不要立即制作完整游戏。  
  
先实现一个可以运行的 Vertical Slice。  
  
场景：  
  
一个夜晚的日式雪景庭院。  
  
场景中只有：  
  
* 玩家摄像机  
* 一个AI少女角色  
* 雪  
* 灯笼  
* 桥  
* 水/温泉  
* 简单环境音  
  
AI角色站在场景中。  
  
玩家可以：  
  
1. 移动/观察角色  
2. 靠近角色  
3. 与角色对话  
4. 观察角色的表情和动作  
5. 让角色根据对话产生不同反应  
  
第一阶段重点不是地图，而是：  
  
“AI + 角色 + 游戏世界”的完整闭环。  
  
⸻  
  
2. AI不是聊天窗口  
  
不要实现：  
  
Player Input  
↓  
LLM  
↓  
Text Response  
  
而是：  
  
Player Input  
↓  
Game State  
↓  
Perception  
↓  
Memory Retrieval  
↓  
Personality  
↓  
Emotion  
↓  
Relationship  
↓  
Decision  
↓  
LLM  
↓  
Structured Response  
↓  
Game Actions  
↓  
Animation / Expression / Speech  
↓  
World State Update  
↓  
Memory Update  
  
LLM负责“理解、思考、表达和选择行为”。  
  
游戏引擎负责“执行行为”。  
  
⸻  
  
3. AI Character State  
  
创建 AICharacterState：  
  
interface AICharacterState {  
    name: string;  
    mood: string;  
    emotionIntensity: number;  
    relationshipLevel: number;  
    trust: number;  
    affection: number;  
    energy: number;  
    currentActivity: string;  
    currentGoal: string;  
    currentLocation: string;  
    recentEvents: GameEvent[];  
    personality: PersonalityProfile;  
}  
  
这些状态必须真正参与 AI 决策。  
  
不要只作为 UI 数据。  
  
例如：  
  
relationshipLevel 很低：  
  
AI：  
“嗯……你好。”  
  
relationshipLevel 较高：  
  
AI：  
“你终于来了，我刚才还在想你什么时候会过来。”  
  
⸻  
  
4. Personality  
  
设计一个稳定的人格系统。  
  
例如：  
  
interface PersonalityProfile {  
    traits: {  
        warmth: number;  
        curiosity: number;  
        playfulness: number;  
        shyness: number;  
        confidence: number;  
        empathy: number;  
    };  
    speakingStyle: string;  
    values: string[];  
    boundaries: string[];  
    likes: string[];  
    dislikes: string[];  
}  
  
人格不能每次请求LLM时随机变化。  
  
同一个角色必须拥有长期一致的人格。  
  
⸻  
  
5. Emotion System  
  
至少实现：  
  
* happy  
* sad  
* shy  
* curious  
* surprised  
* worried  
* embarrassed  
* angry  
* calm  
* lonely  
  
情绪不是简单的“LLM输出文字”。  
  
它必须影响：  
  
* 对话内容  
* 语气  
* 表情  
* 动作  
* 注视方向  
* 身体姿态  
* 主动行为  
  
例如：  
  
emotion = shy  
  
那么：  
  
expression = shy  
  
animation = look_away  
  
voiceStyle = softer  
  
dialogueStyle = hesitant  
  
这些状态必须统一。  
  
⸻  
  
6. Game Perception  
  
AI必须能够知道自己所处的世界。  
  
建立：  
  
interface WorldState {  
    timeOfDay: string;  
    weather: string;  
    playerPosition: Vector3;  
    playerDistance: number;  
    playerActivity: string;  
    characterPosition: Vector3;  
    nearbyObjects: WorldObject[];  
    nearbyCharacters: Character[];  
    recentEvents: GameEvent[];  
}  
  
不要把整个游戏世界原封不动发送给LLM。  
  
建立 Context Builder：  
  
Game World  
↓  
Relevant State  
↓  
AI Context  
↓  
LLM  
  
只提供与当前决策相关的信息。  
  
⸻  
  
7. Memory System  
  
这是这个项目的核心功能之一。  
  
不要把所有聊天记录无限塞进 context。  
  
实现：  
  
Short Term Memory  
  
当前对话。  
  
Episodic Memory  
  
重要事件。  
  
例如：  
  
“玩家第一次带我来到雪地。”  
  
Relationship Memory  
  
例如：  
  
“玩家曾经答应过陪我看烟花。”  
  
Preference Memory  
  
例如：  
  
“玩家喜欢下雪的晚上。”  
  
World Memory  
  
例如：  
  
“桥边的灯笼每晚都会亮。”  
  
⸻  
  
AI每次对话前：  
  
Current Situation  
+  
Relevant Memories  
+  
Relationship State  
+  
Personality  
+  
Emotion  
  
然后再交给LLM。  
  
AI回复之后：  
  
判断这次事件是否值得形成长期记忆。  
  
不要保存所有内容。  
  
⸻  
  
8. Structured AI Output  
  
LLM不能只返回字符串。  
  
要求模型返回结构化 JSON。  
  
例如：  
  
{  
  "dialogue": "你来了啊……我刚才还在想你。",  
  "emotion": {  
    "name": "happy",  
    "intensity": 0.72  
  },  
  "intent": "greet_player",  
  "actions": [  
    {  
      "type": "look_at_player"  
    },  
    {  
      "type": "smile"  
    }  
  ],  
  "relationshipDelta": 1,  
  "memoryCandidate": {  
    "shouldRemember": false  
  }  
}  
  
游戏引擎读取 JSON。  
  
然后执行：  
  
dialogue  
→ UI / TTS  
  
emotion  
→ Animator / Facial Expression  
  
actions  
→ Game Engine  
  
relationshipDelta  
→ Relationship System  
  
memoryCandidate  
→ Memory System  
  
⸻  
  
9. Tool System  
  
LLM不能直接执行任意代码。  
  
建立安全的 Tool Layer。  
  
例如：  
  
lookAtPlayer()  
moveTo(position)  
followPlayer()  
playAnimation(animation)  
setExpression(expression)  
inspectObject(objectId)  
getNearbyObjects()  
getWorldTime()  
startActivity(activity)  
giveItem(itemId)  
remember(event)  
  
LLM只能调用这些工具。  
  
游戏程序负责真正执行。  
  
⸻  
  
10. Autonomous Behavior  
  
AI不能永远等待玩家输入。  
  
建立简单的 AI autonomous loop：  
  
Every few seconds:  
Observe World  
↓  
Evaluate Current Goal  
↓  
Evaluate Mood  
↓  
Evaluate Player  
↓  
Decide Whether To Act  
↓  
Action  
  
例如：  
  
玩家没有和AI说话：  
  
AI可能：  
  
* 看雪  
* 看灯笼  
* 坐下来  
* 走到桥边  
* 看向玩家  
* 主动说一句话  
* 继续自己的活动  
  
这样AI才具有“生命感”。  
  
⸻  
  
11. Attention System  
  
实现角色注视系统。  
  
角色应该能够：  
  
* 看玩家  
* 看玩家手中的物品  
* 看附近发生的事情  
* 看环境  
* 偶尔移开视线  
  
不要让角色永远机械地盯着摄像机。  
  
Attention Target 应由 AI / 游戏状态决定。  
  
⸻  
  
12. Animation System  
  
AI输出：  
  
{  
    "emotion": "shy",  
    "animation": "look_away",  
    "expression": "embarrassed"  
}  
  
游戏引擎负责映射。  
  
建立：  
  
AI semantic action  
↓  
Animation Controller  
↓  
实际动画  
  
例如：  
  
happy → smile  
sad → lower_head  
shy → look_away  
surprised → widen_eyes  
angry → tense  
calm → idle  
  
不要让LLM直接控制Animator参数。  
  
⸻  
  
13. Dialogue  
  
玩家可以输入：  
  
“你在这里做什么？”  
  
AI根据：  
  
* personality  
* currentActivity  
* mood  
* relationship  
* memory  
* worldState  
  
生成回复。  
  
例如AI当前正在看雪：  
  
“我在看雪。  
  
你不觉得这里的雪特别安静吗？”  
  
如果玩家之前说过喜欢雪：  
  
“你之前不是说你喜欢下雪吗？  
  
所以我想……如果你来的话，也许你会喜欢这里。”  
  
第二句话必须能够来自 Memory System。  
  
⸻  
  
14. Relationship System  
  
实现：  
  
relationshipLevel  
trust  
affection  
familiarity  
  
这些变量不要简单地根据每句话 +1。  
  
根据事件类型和上下文改变。  
  
例如：  
  
玩家帮助AI：  
trust + 3  
  
玩家记住AI喜欢的东西：  
affection + 2  
  
玩家长时间忽略AI：  
loneliness + 1  
  
玩家做出让AI不舒服的事情：  
trust - 3  
  
关系变化应该缓慢、连续。  
  
⸻  
  
15. Voice  
  
如果技术栈允许，实现：  
  
Player microphone  
↓  
Speech To Text  
↓  
AI  
↓  
Text  
↓  
Text To Speech  
↓  
Character Voice  
  
第一阶段可以先使用文字输入。  
  
但架构必须预留语音接口。  
  
LLM Provider、STT、TTS都应该抽象。  
  
例如：  
  
interface LLMProvider {}  
interface STTProvider {}  
interface TTSProvider {}  
  
不要把某一家API写死。  
  
⸻  
  
16. Camera  
  
摄像机不要只是普通第三人称相机。  
  
当AI和玩家进行重要对话时：  
  
* AI可以主动面向玩家  
* 摄像机可以轻微调整  
* AI靠近时可以改变镜头距离  
* 情绪变化可以配合镜头  
  
但是第一阶段不要制作复杂的电影化镜头。  
  
优先保证稳定互动。  
  
⸻

18. MVP成功标准  
  
完成后，我应该能够：  
  
1. 启动游戏  
2. 进入雪夜场景  
3. 看到AI角色  
4. 靠近她  
5. 输入一句自然语言  
6. AI理解我的话  
7. AI根据人格生成回复  
8. AI根据情绪改变表情  
9. AI执行动作  
10. AI记住重要事件  
11. 离开后回来  
12. AI仍然记得重要事件  
13. AI能够偶尔主动行动  
  
最终测试：  
  
我第一次告诉AI：  
  
“我很喜欢这里的雪。”  
  
然后离开。  
  
过一段时间重新回来。  
  
我问：  
  
“你还记得我喜欢什么吗？”  
  
AI应该能够根据 Memory System 回答。  
  
这才证明 Memory 真正工作。

20. 非常重要  
  
不要为了完成需求而伪造AI能力。  
  
如果某个功能实际上只是：  
  
if relationship > 50:  
say(“我想你了”)  
  
不要把它包装成真正的AI。  
  
我要的是：  
  
LLM负责理解和决策，  
  
Game Engine负责执行，  
  
Memory负责连续性，
