# 当前开发方向与边界

整理日期：2026-10-11；2026-10-14补只读接续现状。依据用户2026-10-10的直接继承澄清、五项目调查讨论与2026-10-11的先梳理要求。本文汇总已经明确的方向，不冻结新的产品架构或未答选择。

## 已明确的方向

Aimy 是虚拟情感陪伴产品，优先陪用户打游戏、看视频及日常交流。桌面角色是呈现方式，情感关系可以发展，阶段和好感数字为辅助机制。

产品以 AIRI 原版完整 `apps/stage-tamagotchi` 为起点，保留原有界面、窗口、角色与对话结构。先完成主工程继承和品牌/必要界面定制，让用户实际使用，再按体验补足记忆、自然语音、表现与主动陪伴。

旧 `digital-lover/apps/aimy-desktop` 是独立组装的精简样机，保留作历史与缺陷验证参考。其UI、会话、桥接、音频装配和窗口规则不整体迁入新主线。同名包与锁文件不覆盖叠加。

## 产品边界

- macOS优先、本地优先、少量受邀用户BYOK、一个主要角色、无摄像头，一期不做露骨内容；保留未成年人基础保护与危机/自伤兜底要求。
- 支持文字、分享图片、可插话的连续语音、独立授权看屏及协调的人物反馈。
- 会话、关系、已确认记忆和设置需要可靠保存与恢复；记忆还需来源、纠正、删除和跨重启验证，聊天记录保存不能替代事实召回。
- 原版已有的电脑工具、云同步等入口不自动纳入一期；游戏代操作、独立游戏世界、订阅与用户自建角色仍后置。
- 先用原版示例验证，已记录实测的是Live2D；正式角色格式、人设、模型和音色尚未定稿，旧“必须VRM”不生效。

## 已作答事项（2026-10-13）

此前三项待答选择已由用户作答，记录见 [三项产品行为与立项方法](../01-决策记录/2026-10-13-三项产品行为与立项方法.md)：

1. **收起聊天 = 桌面角色继续陪伴**。她留在桌面，用户能看见她。目标已明确；10-14复核提醒，独立聊天窗口与主舞台close→hide须分别验收，不能仅用主舞台hide证明收起聊天后的可见性，不自动新增或重写窗口代码。
2. **记忆自动保存**，不需要用户确认；保存的价值在于以后**主动提起**，而不是等用户检索。复核确认默认桌面陪伴的可靠持久事实闭环未形成；独立task-memory已有合并/限额/来源轮次guard，应先审用可用纯叶子，再补本期持久事实/来源/管理。不能泛称上游完全无记忆基础。
3. **低费用观察 = 间隔看一眼**。上游已有3000ms心跳、忙帧跳过、视觉读取队列和上下文替换。10-14复核确认普通Vision设置已有间隔/统计，完整source/start/stop控制仍在开发者工具页；需补的是产品入口、反馈和撤权/陈旧结果保护，不能说整条视觉链或全部界面缺失。
