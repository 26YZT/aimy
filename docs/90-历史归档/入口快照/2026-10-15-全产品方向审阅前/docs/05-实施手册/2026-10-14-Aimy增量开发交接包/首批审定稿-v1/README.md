### 这次请审定的具体方案

这些是本稿新收敛的工程与交互提案，**不是把过去选过的 A 自动当成同意**。

| 审定项 | 本稿建议 | 对使用的影响 |
|---|---|---|
| R1 复用方式与存储 | AIRI 单一运行链；Aions/Ryza 只移植清单内规则；沿既有 IndexedDB，补同一作用域原子记忆账本 | 不运行候选的 Python 服务、不新增向量库；移植后的代码必须重新验证 |
| R2 首次认识与启用 | 资料放在模型选择后，可全跳过；首批功能启用时开始记录新来源，关闭自动整理期间不补记 | 资料未填不挡聊天；自由文字整理失败保留待处理，不冒称已理解 |
| R3 查看与维护 | 关于我以查看为主、资料维护折叠；日常自然聊天更正，关联清理由产品自动处理 | 用户只操作目标，不裁决关联集合；独立记忆和聊天保留，本批不加清空所有记忆按钮 |
| R4 工程基线 | 先验现有 Node24.20.0/pnpm11.24.0，验证通过后对齐版本声明；后续用独立开发 profile | 不顺手升级、迁移或清空旧数据；独立目录需先确认实际状态 |
| R5 验收合同 | 本稿工程硬门全部闭合，8例逐场景核事实/召回/表达；原模型评测推进至目标卡审定 | 不用固定输出测试冒充语义通过，不用总均分掩盖硬门失败；¥10为一次验收总额 |

**本稿不增加关系数值系统、领域知识库、电脑自动操作或外部发信。** 正式角色模型、音色、美术和发行范围不作为文字记忆批次的隐含选型。许可通知随实际移植保留，资源不连带搬入。
