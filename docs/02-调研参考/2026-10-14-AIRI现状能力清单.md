## 主要数据与控制链

文字和图片经现有 chat/context 端口进入 `core-agent`，由角色卡的 system prompt、近期历史、外部上下文和工具结果组成请求，按 Chat Completions 或 Responses 处理，再投影文本、语音与角色动作。新增记忆应为该链提供有来源和当前有效状态的上下文，不另开第二套聊天历史。

麦克风共享输入由订阅持有；VAD 插件在 speech-onset 时把当前会话的 activeTurns 交给 VoiceController。输入 attempt 保留前卷，等待旧回复播放的 silence receipts；输出停止播放组并 abort 生产者。这条已接线机制与未被使用的旧 `voice-input-suppression.ts` 不是同一条链，不能因为后者没有调用者就否定打断能力。

看屏从屏幕源授权、MediaStream、缩放取帧、间隔 ticker、VisionReadQueue、推理到 ReplaceSelf 上下文。普通设置页面已有间隔与统计；完整 source/start/stop 控制仍在开发工具页。当前 stopTicker 主要清理定时器，processCapture 在 await 后发布上下文；关闭后在飞任务与授权代次重检是后续需证明的边界，不能用“停止取帧”代替“拒绝陈旧结果”。

主动性由 App 初始化 character orchestrator，订阅 Spark 事件与到期任务，经通知 Agent 产生反应/命令。notebook 的 note、diary 与 task 已有内存 API，尚非持久化事实库。补持久规则、静默时段、冷却、用户上下文、预算和取消可建立增量候选，不先换调度器。当前 App 卸载未见调用 orchestrator.dispose，而该 dispose 本身也只停 ticker/退订、不清队列或取消在飞请求；关闭后的结果失效必须另补证据。


登录后的数据路径需单独处理。Provider store会自动同步完整用户Provider config；非local用户的聊天有outbox/WS云发送，匿名local路径跳过。角色卡云同步默认关只管角色卡，不关闭上述路径。这些是客户端源码事实，本轮没有读取用户当前配置/登录态/聊天，也没有核实远端存储或加密策略；不能据此称已经发生泄露，也不能把“本地优先”记作验收通过。

## 真正需要比较的增量

- 自动事实记忆：用户原要求是自动保存、以后主动提；需来源、当前有效版本、纠正、删除及重启证据，不能退回每条手工确认。

## 对历史结论的纠正

1. “AIRI 没有主动性”过宽：Spark 通知 Agent、队列、2 秒 ticker 与任务 API 已存在；缺的是持久策略和具体体验。
2. “AIRI 没有真正语音打断”不成立：当前 VoiceActivityPlugin 到 VoiceController 的 speech-onset 链已核到；自动插话仍有回声消除门控。
3. “所有看屏界面都藏在 devtools”过宽：正式 Vision 设置已有间隔和统计，完整捕获控制仍在 devtools。
4. “Chromatic 主题只能在 Storybook 改”过宽：正式 color-scheme 页面已有色相和动态开关。
5. “memory 包存在所以有长期记忆”不成立；反过来“没有长期记忆所以没有任何历史或摘要”也不成立。
6. 未设置 contextIsolation/nodeIntegration 不是它们被关闭的证据；插件权限检查也不是进程/内存沙箱的证据。本次只记录显式设置与已核调用。
7. 收起聊天、隐藏主舞台和退出不是同一动作。主窗口 close 被转成 hide，不能据此直接证明“收起聊天角色仍可见”或“隐藏会停采集”；需按各窗口入口与产品语义分别验收。
