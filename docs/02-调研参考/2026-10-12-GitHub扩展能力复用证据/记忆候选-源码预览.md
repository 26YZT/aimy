## 决策结论

**最值得先评估的是 Mem0 的 TypeScript OSS 薄适配，以及 MemOS/Hippo 的少量检索与记忆治理模块。四个重点项目均不能整仓复制后宣称满足 Aimy 的可靠长期记忆。**

Aimy 需要的是记住用户明确说过的事实、说明来源、支持纠正和删除、重启能恢复。框架提供的技能学习、项目知识、自动回放和图数据库不应自动变成产品功能。聊天记录仍由 AIRI 保管；记忆记录引用 AIRI 的稳定会话/消息 ID，候选只读取所需内容、输出候选事实或检索结果。自动保存还是用户确认保存仍是待定产品选择。

## 1. Mem0：优先比较 OSS TS，但不能把 delete 等同完整遗忘

本轮固定 `b7ad69afda6b6ed030347c66d48a13e4de9dec08`，HEAD 提交时间 `2026-10-07T13:06:15Z`。根 LICENSE 与 TS package 都为 Apache-2.0。TS package 版本 3.3.1，exports 区分默认 API 客户端与 `./oss`；应评估 OSS，不要误接托管 API 默认入口。[源码1](https://github.com/mem0ai/mem0/blob/b7ad69afda6b6ed030347c66d48a13e4de9dec08/mem0-ts/package.json#L18-L28)

全局模块是 hosted client / OSS Memory / embeddings / LLM adapters / vector stores / history storage / prompts / rerankers。`Memory.add` 先规范化 user/agent/run scope，`infer=true` 检索已有事实后做一轮 LLM 提取；`infer=false` 可只存已确认输入。`search` 合并语义与可选关键词检索，`update` 更换向量与元信息后记录旧值，`delete` 删除当前向量后记历史。这个分层可放在 AIRI 内部记忆边界后，避免复制第二份聊天 UI、provider 配置或音频链路。[提取链](https://github.com/mem0ai/mem0/blob/b7ad69afda6b6ed030347c66d48a13e4de9dec08/mem0-ts/src/oss/src/memory/index.ts#L890-L935) [确认后存入链](https://github.com/mem0ai/mem0/blob/b7ad69afda6b6ed030347c66d48a13e4de9dec08/mem0-ts/src/oss/src/memory/index.ts#L846-L864)

一个需要纠正的旧印象：当前 TS OSS 的 `vectorStore.provider='memory'` **实际使用 better-sqlite3 文件持久化，并非纯内存**。但默认路径、原生 addon/Electron ABI、SQLite 历史与向量数据分开的一致性仍要专门验证，不能因为有表就说重启恢复已通过。[存储实现](https://github.com/mem0ai/mem0/blob/b7ad69afda6b6ed030347c66d48a13e4de9dec08/mem0-ts/src/oss/src/vector_stores/memory.ts#L40-L66)

确定的功能缺口：`deleteMemory` 将 `prevValue` 送进 `db.addHistory(..., 'DELETE')`。SQLite history schema 持有 `previous_value/new_value`，另外存在 `messages.content`。所以「从召回中移除」不等于「从所有副本彻底删除」。实体清理错误仅 warning 后继续，当前删除链也没有展示所有 linked facts/源消息的一起清除。单项遗忘需要额外确定性流程，或者在适配器中关闭/替换这套 history，按 AIRI 的删除要求维护唯一来源关系。[删除代码](https://github.com/mem0ai/mem0/blob/b7ad69afda6b6ed030347c66d48a13e4de9dec08/mem0-ts/src/oss/src/memory/index.ts#L2018-L2045) [历史表](https://github.com/mem0ai/mem0/blob/b7ad69afda6b6ed030347c66d48a13e4de9dec08/mem0-ts/src/oss/src/storage/SQLiteManager.ts#L17-L67)

默认配置使用 OpenAI embedding/LLM，并非纯本地模型；遥测默认开启，可由 `MEM0_TELEMETRY=false` 关闭。本轮未断言遥测会传聊天正文，源码确认的是事件/配置遥测开关。BYOK 可以做，配置应经过 AIRI 密钥边界；来源 message IDs、用户确认、纠正与后台任务取消不能交给 prompt 自行维护。[默认模型](https://github.com/mem0ai/mem0/blob/b7ad69afda6b6ed030347c66d48a13e4de9dec08/mem0-ts/src/oss/src/config/defaults.ts#L3-L34) [遥测](https://github.com/mem0ai/mem0/blob/b7ad69afda6b6ed030347c66d48a13e4de9dec08/mem0-ts/src/oss/src/utils/telemetry.ts#L13-L25)

**适配量：中。** 不建议复制巨大 `memory/index.ts` 和全部 provider。可以比较锁定版本的 OSS 包与「只复用检索函数、自管记忆账本」两条路线；按中文事实准确率、纠正及时性、完整遗忘及调用成本选择。

## 2. MemOS：中文召回小模块有价值，插件与日志策略要隔离

固定 `a7367d07e55db61099f7b4e2c1108bc5831a24f3`，HEAD `2026-09-22T01:51:03Z`；不要把近期 GitHub updated_at/pushed_at 当源码最新提交。深审的是 `apps/memos-local-plugin/core/`，不是根 Python Memory OS 或云版插件。模块包括 capture / session & episode / L1-L3 memory / retrieval / reward / feedback / skill / world model / SQLite storage / model adapters / logging / telemetry。宿主适配目标是 OpenClaw/Hermes/DeepSeek，不是 AIRI。

最可拆的是 `core/storage/keyword.ts`：FTS 字符清洗、CJK 边界、两字中文片段、exact identifier 提取及 reciprocalRankScore。它是低运行依赖的工具模块，可拿来处理「小王」「星露谷」「上次说的电影」这类短句检索，但通用噪声字过滤是否错伤人名需要 Aimy 中文样本验证。`storage/vector.ts` 的向量编码/余弦函数亦可定向提取；整体文件带 rootLogger 和 DB scan，不能照搬模块路径不加拆分。[FTS](https://github.com/MemTensor/MemOS/blob/a7367d07e55db61099f7b4e2c1108bc5831a24f3/apps/memos-local-plugin/core/storage/keyword.ts#L76-L113) [中文短词](https://github.com/MemTensor/MemOS/blob/a7367d07e55db61099f7b4e2c1108bc5831a24f3/apps/memos-local-plugin/core/storage/keyword.ts#L148-L194)

复杂 ranker 的 RRF/MMR/阈值与候选去重值得比较，但它导入 reward/backprop、插件契约和特定 candidate 类型；L2/L3 对应任务经验/技能，不天然等同陪伴用户事实。应改成 Aimy 的候选事实、确认状态、来源、时间与预算类型后再验证，不建议整套技能强化/自主学习进入一期。[ranker 依赖](https://github.com/MemTensor/MemOS/blob/a7367d07e55db61099f7b4e2c1108bc5831a24f3/apps/memos-local-plugin/core/retrieval/ranker.ts#L42-L59)

明确边界：trace delete 清 FTS 和 traces；trace edit 只改用户可见正文，不改向量。policy 表虽存 episode/trace/feedback IDs，但这些 JSON 来源字段不能单独证明删除原 trace 会失效派生 policy、world model 和摘要。本轮没有完整追踪 viewer 上层联动，不把 repo 方法不足直接扩大为已复现全产品故障；要测上层补偿与重启后召回一致性。[trace 编辑/删除](https://github.com/MemTensor/MemOS/blob/a7367d07e55db61099f7b4e2c1108bc5831a24f3/apps/memos-local-plugin/core/storage/repos/traces.ts#L746-L789) [来源字段](https://github.com/MemTensor/MemOS/blob/a7367d07e55db61099f7b4e2c1108bc5831a24f3/apps/memos-local-plugin/core/storage/repos/policies.ts#L30-L44)

配置默认 `telemetry.enabled=true`，`llmLog.enabled=true` 且 prompt/completion 均不脱敏。Aimy 陪伴内容不能继承此默认日志策略。根 LICENSE 是 Apache-2.0，但本地 plugin package 声明 MIT、其目录没有独立 LICENSE 文件；拆取前要明确文件适用许可证与保留通知，不凭 package 字段把根授权换成 MIT。Node>=20、better-sqlite3 和 Transformers 也是实际依赖。[默认日志](https://github.com/MemTensor/MemOS/blob/a7367d07e55db61099f7b4e2c1108bc5831a24f3/apps/memos-local-plugin/core/config/defaults.ts#L340-L356) [package](https://github.com/MemTensor/MemOS/blob/a7367d07e55db61099f7b4e2c1108bc5831a24f3/apps/memos-local-plugin/package.json#L87-L109)

**适配量：纯词法小模块低；ranker 中；完整插件高。** 首轮只验证中文检索模块，排除宿主 agent 生命周期、UI、hub、自动技能执行与默认日志。

## 3. Hippo：新发现的 TS 参考，纠正/防回写设计强于整体接入价值

固定 `beea545715e6f62936f3204cd4a48fc7ef61a722`，HEAD `2026-10-11T23:00:42Z`，MIT；package 2.0.0。全局为 core memory / db & store / hybrid search / embedding/reranking / consolidate sleep / trust / API/CLI/MCP / coding-tool hooks / connectors / dashboard。它有公开 `store-kit` 端口，但端口覆盖 goals、projects、audit、continuity、keys、predictions 等，不能因为有接口就把它当轻量陪伴 SDK。[入口](https://github.com/kitfunso/hippo-memory/blob/beea545715e6f62936f3204cd4a48fc7ef61a722/package.json#L8-L15)

`src/search/rrf.ts` 无运行时 imports，是真正可拆的小函数：N 路排名融合，参数与输入校验清楚。`MemoryEntry` 的 source、parents、source_session_id、superseded_by、summary_dirty，显式 successor 更正、摘要变脏以及拒绝值 tombstone 的思想很符合 Aimy 防止纠正内容被重新提取的问题。但情绪权重/decay、coding 成功失败奖励和项目作用域需要产品解释，不能自动成为关系值或记忆判断标准。[纯 RRF](https://github.com/kitfunso/hippo-memory/blob/beea545715e6f62936f3204cd4a48fc7ef61a722/src/search/rrf.ts#L5-L54) [来源/更正字段](https://github.com/kitfunso/hippo-memory/blob/beea545715e6f62936f3204cd4a48fc7ef61a722/src/core/memory.ts#L33-L81) [更正写入](https://github.com/kitfunso/hippo-memory/blob/beea545715e6f62936f3204cd4a48fc7ef61a722/src/api/promote.ts#L43-L74)

存储使用 Node 内置 `node:sqlite`，package 要求 Node>=22.16，必须先核验 AIRI Electron 内置 Node 和隔离进程，不等同普通浏览器 TS。默认本地 embedding 是英文 MiniLM，中文可靠召回与模型分发许可证仍要单独验证。该项目没有以托管 API 客户端为核心；但整仓钩子/连接器是 coding tooling，不应一起拆进 Aimy。[运行时](https://github.com/kitfunso/hippo-memory/blob/beea545715e6f62936f3204cd4a48fc7ef61a722/src/db/sqlite.ts#L20-L27) [最低 Node](https://github.com/kitfunso/hippo-memory/blob/beea545715e6f62936f3204cd4a48fc7ef61a722/package.json#L88-L113)

这里要避免把删除能力说得过于弱或过于强：它**确实有** raw archive、reject 和 dormant 副本清理。raw archive 不保留原内容，只保留 metadata；reject 在事务中处理 live/dormant 后再清磁盘镜像。可是镜像 purge 是 best effort，失败可能留文件；by-ID reject 拒绝 personal memory，提示走 forget；tombstone 根据归一化文本 digest，不等于语义同义改写都不会回写。Aimy 的一键遗忘要对原记录、派生摘要、embedding、镜像与异步写入做统一确定性处理，不直接把 `forget`/`reject` 单个 API 名称当完整证明。[raw 移除](https://github.com/kitfunso/hippo-memory/blob/beea545715e6f62936f3204cd4a48fc7ef61a722/src/store/raw-archive.ts#L35-L60) [reject 流程](https://github.com/kitfunso/hippo-memory/blob/beea545715e6f62936f3204cd4a48fc7ef61a722/src/store/rejected-values.ts#L122-L164) [镜像残留](https://github.com/kitfunso/hippo-memory/blob/beea545715e6f62936f3204cd4a48fc7ef61a722/src/store/mirrors.ts#L212-L230)

**适配量：RRF 低；纠正规则中；整套 store 高。** 推荐拿纯函数和来源/更正/拒绝回写规则做小范围对比，暂不整包替换 AIRI 记忆。

## 4. Memvid：并非只有检索，但版本/遗忘语义值得先挡住

固定 `e6bd9f7b9c38cd8d5370fa0fc936ac1dcd751813`，HEAD `2026-07-14T14:39:06Z`，Apache-2.0。当前为 Rust v2 单 `.mv2` 文件引擎，不能沿用旧 QR/video storage 的描述。全局包含 ingest/chunking / WAL & commit/footer / lex(Tantivy) / vectors / image CLIP / Whisper / time index / memory cards / schema / encryption / readers / replay。官方 README 列 Node SDK，但本轮深审的是 Rust 核心；SDK 二进制分发和 macOS arm64 包还没有核验，不能报可直接 npm 接入。[Cargo](https://github.com/memvid/memvid/blob/e6bd9f7b9c38cd8d5370fa0fc936ac1dcd751813/Cargo.toml#L1-L13) [特性开关](https://github.com/memvid/memvid/blob/e6bd9f7b9c38cd8d5370fa0fc936ac1dcd751813/Cargo.toml#L99-L131)

它并非纯向量引擎：MemoryCard 有 entity/slot/value、time/更新关系、source_frame_id 与 source_uri，能表达偏好和事实。可作为本地知识检索候选；Aimy 情感事实确认、来源连接、删除与纠正仍需外层治理。[memory card](https://github.com/memvid/memvid/blob/e6bd9f7b9c38cd8d5370fa0fc936ac1dcd751813/src/types/memory_card.rs#L176-L219)

明确风险有二。第一，`delete_frame` 写 WAL tombstone，逻辑删除当前 frame 并去索引；物理 payload 在 vacuum 才整理，源帧删除链中没有展示对应 MemoryCard 的同步删除，不能把删除 frame 当彻底忘记事实。第二，`MemoriesTrack.get_current/get_at_time` 按时间倒排后寻找第一张 `!is_retracted()` 卡；根据这一实现，最新卡为 retract 时会跳过而有返回旧卡的风险，且该查询不检查源帧状态。本轮为静态风险，未跑复现；选择引擎前必须用「我喜欢咖啡→删除/撤回咖啡→重启→你记得我喜欢什么」测试证实语义。[WAL 删除](https://github.com/memvid/memvid/blob/e6bd9f7b9c38cd8d5370fa0fc936ac1dcd751813/src/memvid/mutation.rs#L3244-L3300) [vacuum](https://github.com/memvid/memvid/blob/e6bd9f7b9c38cd8d5370fa0fc936ac1dcd751813/src/memvid/mutation.rs#L3013-L3045) [撤回查询](https://github.com/memvid/memvid/blob/e6bd9f7b9c38cd8d5370fa0fc936ac1dcd751813/src/types/memories_track.rs#L363-L394)

本地 text embedding 默认 offline，并默认英文 BGE-small。CPU/内存、中文模型、native ABI、写入后 commit 及损坏恢复、密码加密特性和模型资源许可证都需独立验证。Apache 代码授权不自动覆盖 CLIP/Whisper/embedding 权重。不要为了借用多模态存储就让它长期留原始截图/录音。[embedding registry](https://github.com/memvid/memvid/blob/e6bd9f7b9c38cd8d5370fa0fc936ac1dcd751813/src/text_embed.rs#L170-L225) [默认离线](https://github.com/memvid/memvid/blob/e6bd9f7b9c38cd8d5370fa0fc936ac1dcd751813/src/text_embed.rs#L249-L260)

**适配量：高。** 后期可比较单文件检索，当前不建议作为一期核心用户事实存储。

## 较浅候选与边界

Cognee 当前 Python 核心有 temporal graph、record_provenance 与 delete/forget 目录；本地 LanceDB/Ladybug 不要求使用其云服务。但 pyproject 包含平台版本处理和多个 native 数据引擎。它能贡献来源/删除图设计，直接复制进 Vue/Electron 不可行。这里不假定所有删除已可靠。详见 evidence 中 pyproject、cognify 与 add 代码。

Graphiti 当前默认 Neo4j，另有 Kuzu/FalkorDBLite 嵌入式选择；时间事实/episode API 很适合后续「以前与现在」记忆。Python 进程、图驱动及 LLM 提取负担对少用户 desktop 一期仍偏大。将其留为真实时序/多跳缺口明确后的独立服务候选。

LongMemory 是新增 TS 候选，包含实体解析、grounding、bitemporal、关联召回与 SQLite。当前 public exports 是较大的 library/CLI/API，不是只包装 query 的小库。它的领域仍包含 projects/coding；本轮未完整追踪删除，不建议在 Mem0/Hippo 比较前直接升级为主选择。

Memobase 的 user-profile 方向有意义，但本次重验 HEAD 日期仍为 2026-01-11；技术栈为 Python FastAPI、Postgres/pgvector 和 Redis。参考画像 schema，整套部署后置。

MegaMemory 本轮只核验目录/元数据，未深审，默认不列推荐安装。记忆领域相同并不说明适用于陪伴用户事实。

## 接入顺序建议与验收前置

1. 完整 AIRI 基线实际使用后确认记忆缺口；给会话/消息建立稳定来源引用，先定义「候选事实→确认状态→纠正→完整删除→重启恢复」契约。是否自动写记忆仍保持待答。
2. 第一轮只比较 MemOS 中文检索小函数、Hippo RRF 或 AIRI 已有等价实现。遇到重复只保留一个。此步能帮助检索，但不会凭空完成事实识别。
3. 在统一契约后做 Mem0 TS OSS 薄适配试验，与自管确定性 SQLite 事实账本比较；共享 AIRI 模型与密钥边界，明确关闭候选遥测和内容日志。确认组件能替换且避免双权威。
4. 只有中文复杂时间与关系召回明确不足时，再比较 Graphiti/Cognee；需要大量本地文档/单文件检索时再比较 Memvid。不叠加几个完整记忆框架。

任何路线至少分别提供：写入来源与主体正确、模型猜测不当确认事实、同义中文召回、显式更正立即替代旧值、遗忘不在历史/摘要/向量/镜像和重启后复活、关闭与取消拒绝陈旧后台结果、导入旧聊天不会重新灌入已删事实、空数据/损坏文件恢复、本地低配 CPU/内存与 BYOK 调用费用证据。本报告没有执行这些验收，也没有把 GitHub benchmark/星标数量视为 Aimy 的产品通过。
