这些项目不能整仓复制后直接成为 Aimy 的新能力。可以拆入的主要是输入输出清楚、不会拥有第二套会话/音频/权限/存储的叶子模块；完整运行时、桌面应用和角色制作工具要隔离使用。

## 一、记忆能力

### 记忆候选总体判断

本轮广搜并固定 9 个候选；Mem0、MemOS 本地插件、Hippo Memory、Memvid 做了写入/召回/更新/删除/存储链路的重点静态阅读。所有项目均未安装或运行。

### Mem0：最接近薄适配器，但不是完整遗忘系统

固定 HEAD 为 `b7ad69afda6b6ed030347c66d48a13e4de9dec08`，默认分支提交日期为 `2026-10-07`，根许可证为 Apache-2.0。TS 包明确区分 hosted client 与 `./oss`，应只评估 OSS 路径。

可以参考 `Memory.add/search/update/delete` 的分层：`infer=false` 可以存已确认输入，`infer=true` 会先检索旧事实再调用抽取模型；scope、vector store 和 history 也有明确边界。当前 TS OSS 的 memory vector provider 实际用 `better-sqlite3` 文件，而不是纯内存。

必须适配的地方是删除语义。删除当前向量后，`deleteMemory` 仍把 `prevValue` 写入 history；实体清理失败只 warning 后继续。Aimy 若要“一键忘记”，必须由自己的确定性删除流程同步处理原消息引用、事实、摘要、向量、历史、镜像和异步队列，不能直接复用这个 delete 名称。

源码证据：[OSS入口和版本](https://github.com/mem0ai/mem0/blob/b7ad69afda6b6ed030347c66d48a13e4de9dec08/mem0-ts/package.json#L18-L28)、[提取链](https://github.com/mem0ai/mem0/blob/b7ad69afda6b6ed030347c66d48a13e4de9dec08/mem0-ts/src/oss/src/memory/index.ts#L890-L935)、[已确认输入存入](https://github.com/mem0ai/mem0/blob/b7ad69afda6b6ed030347c66d48a13e4de9dec08/mem0-ts/src/oss/src/memory/index.ts#L846-L864)、[文件持久化](https://github.com/mem0ai/mem0/blob/b7ad69afda6b6ed030347c66d48a13e4de9dec08/mem0-ts/src/oss/src/vector_stores/memory.ts#L40-L66)、[删除与历史](https://github.com/mem0ai/mem0/blob/b7ad69afda6b6ed030347c66d48a13e4de9dec08/mem0-ts/src/oss/src/memory/index.ts#L2018-L2045)。

建议：把 Mem0 作为“候选事实抽取/语义检索适配器”与自管 SQLite 事实账本进行对照，而不是把 Mem0 当唯一事实数据库。

### MemOS：中文词法模块值得拆，完整本地插件不应整包接入

固定 HEAD `a7367d07e55db61099f7b4e2c1108bc5831a24f3`，提交日期 `2026-09-22`。本轮读的是 `apps/memos-local-plugin/core/`，不是根 Python 服务。`core/storage/keyword.ts` 的 CJK 清洗、两字短片段和 RRF 适合 Aimy 的昵称、游戏名、电影名召回；`ranker.ts` 则与 reward/backprop、宿主类型绑定，不适合直接复制。

trace 删除会清 FTS 和 traces，但 trace body 编辑不会更新向量；本轮没有证明 policy、world model、摘要等派生物已全部失效。默认配置还开启 telemetry 和未脱敏 prompt/completion 日志，不能继承到 Aimy 陪伴内容。根 LICENSE 是 Apache-2.0，但本地 package 字段写 MIT，拆取前要按文件范围复核。

### Hippo 和 Memvid：更适合借治理思想，暂不整包

Hippo 的 `src/search/rrf.ts` 无运行时依赖，是本轮最容易拆出的纯函数。`MemoryEntry` 的 source、parents、source session、superseded_by、summary_dirty 适合转化为 Aimy 的来源/纠正/摘要失效契约；`promote.ts` 的 successor 写入也值得做对照。整库使用 Node>=22.16 的 `node:sqlite`，镜像 purge 失败可能留下文件，不能直接承诺完整遗忘。

Memvid 是 Rust 单文件引擎，memory card 能保存 source frame 和 URI；但删除先写 WAL tombstone，物理 payload 要等 vacuum，`get_current/get_at_time` 跳过撤回卡时可能露出旧值。默认 text embedding 偏英文。它适合后期需要单文件检索时再做独立适配，不适合作为一期核心事实库。

源码证据：[Hippo RRF](https://github.com/kitfunso/hippo-memory/blob/beea545715e6f62936f3204cd4a48fc7ef61a722/src/search/rrf.ts#L5-L54)、[Hippo来源/更正](https://github.com/kitfunso/hippo-memory/blob/beea545715e6f62936f3204cd4a48fc7ef61a722/src/api/promote.ts#L43-L74)、[Hippo镜像清理](https://github.com/kitfunso/hippo-memory/blob/beea545715e6f62936f3204cd4a48fc7ef61a722/src/store/mirrors.ts#L212-L230)、[Memvid删除](https://github.com/memvid/memvid/blob/e6bd9f7b9c38cd8d5370fa0fc936ac1dcd751813/src/memvid/mutation.rs#L3244-L3300)、[Memvid撤回查询](https://github.com/memvid/memvid/blob/e6bd9f7b9c38cd8d5370fa0fc936ac1dcd751813/src/types/memories_track.rs#L363-L394)。

## 二、多模态、连续语音和授权看屏

本轮广搜 11 个仓库，重点深读 Smart Turn、Sherpa-ONNX、N.E.K.O.、TEN VAD；另预览 Pipecat、LiveKit Agents、Screenpipe、Open-LLM-VTuber、RealtimeSTT、RealtimeTTS、TEN Framework。整套 Python/Tauri/RTC 应用都不适合直接覆盖 AIRI 的会话、播放或权限生命周期。

### Smart Turn：第一优先的局部模型适配

固定 `pipecat-ai/smart-turn` HEAD `4786657e242dfe77dd138699ac564ee074a2a543`，提交日期 `2026-01-29`，代码和模型卡为 BSD-2-Clause。它把 16k 单声道音频截取为最近 8 秒、补零、计算 Whisper 特征，再返回“是否说完”的概率。这个接口可以位于 AIRI 现有 VAD/转写旁路，改善“停顿但还没说完”时抢话的问题；它不是插话启动检测器，明确插话的识别与停止播放仍由 AIRI 控制逻辑负责。

不能照抄 README 示例：源码默认文件名与当前 v3.2 artifact 不一致，必须固定 `smart-turn-v3.2-cpu.onnx`、模型 revision、预处理和阈值。Python 预处理需要翻译成 ONNX Worker/Node 适配；每次结果要绑定 session/turn/generation，旧请求完成后不能关闭新一轮。

证据：[推理接口](https://github.com/pipecat-ai/smart-turn/blob/4786657e242dfe77dd138699ac564ee074a2a543/inference.py#L1-L63)、[8秒窗口](https://github.com/pipecat-ai/smart-turn/blob/4786657e242dfe77dd138699ac564ee074a2a543/audio_utils.py#L4-L13)、[Pipecat v3.2路径](https://github.com/pipecat-ai/pipecat/blob/19fca83d2e2336b7c82145fe66b7b1cc76e44ac9/src/pipecat/audio/turn/smart_turn/local_smart_turn_v3.py#L138-L182)。中文、背景游戏音、回声、模型延迟尚未实测。

### Sherpa-ONNX：先验证 AIRI 已有入口

固定 `k2-fsa/sherpa-onnx` HEAD `6e7ea3e409f90aaf1541c87f21a013c4f20b9680`，提交日期 `2026-10-12`，根代码 Apache-2.0。它有 Node addon 的流式 ASR、VAD、在线降噪和 WASM，但 CMake/native addon、macOS arm64打包、模型和退出清理都增加成本。

AIRI 已有 Sherpaw transcription Worker、16k PCM16、AbortSignal、结束 terminate，也有 Apple Speech provider。因此第一顺序是实际验收 AIRI 已有 provider；若性能或降噪确有缺口，再封装 Sherpa-ONNX 的一个接口，不能复制完整 C++ 仓库。

### N.E.K.O.：只借鉴截图代次和响应所有权

固定 `Project-N-E-K-O/N.E.K.O` HEAD `22a9be9215820a85763eb717acbf44cb0acd6d7f`，提交日期 `2026-10-12`。可翻译的思路包括：截图异步返回前检查 generation/source/socket，换源或关闭后丢弃陈旧帧；响应仲裁器等待 provider 终态并在超时后升级 transport；图片附件有数量/字节预算。

现成行为不能照搬：它的屏幕共享与麦克风状态有关，主动视觉可能在手动停止后恢复；默认观察频率不是 Aimy 的低成本策略；token tracker 源码含远端遥测和设备信息。Aimy 要保持屏幕、麦克风独立授权，关闭/隐藏/退出时停止采集并拒绝新调用。

证据：[截图代次检查](https://github.com/Project-N-E-K-O/N.E.K.O/blob/22a9be9215820a85763eb717acbf44cb0acd6d7f/static/app/app-screen.js#L1648-L1762)、[响应仲裁](https://github.com/Project-N-E-K-O/N.E.K.O/blob/22a9be9215820a85763eb717acbf44cb0acd6d7f/main_logic/omni_realtime_client/_response_arbiter.py#L979-L1082)、[屏幕停止语义](https://github.com/Project-N-E-K-O/N.E.K.O/blob/22a9be9215820a85763eb717acbf44cb0acd6d7f/static/app/app-screen.js#L2710-L2828)。这里的代码语言和状态机都需要重写成 AIRI 类型，不能直接复制 Python/JS 大文件。

### TEN VAD、Pipecat、LiveKit、Screenpipe：有价值但暂不接入

TEN VAD 的 C/WASM 接口清楚，但当前许可证有竞争用途和终端应用附加条件，不能只看 Apache 标签；而 AIRI 已有 Silero VAD，先不增加替代。Pipecat 的整套 frame pipeline 和 LiveKit Agents 的 RTC/媒体 server 会制造第二套实时运行时；LiveKit 的 turn detector 模型还受单独模型许可约束。Screenpipe 当前许可证要求商业许可，持续采集和本地历史也不符合一期“获准观察、关闭即停”的边界。

Open-LLM-VTuber 的“用户已经听到的文本再回写 history”和 RealtimeTTS 的分段/字词时序可作体验参考；但它们的 Python 管线、清理任务和播放器不能接管 AIRI。Open-LLM-VTuber 的 `clear()` 静态上没有逐个取消所有已运行 TTS 任务，晚到 payload 风险未运行复现。

|---|---|---|---|
| [VRM Add-on for Blender](https://github.com/saturday06/VRM-Addon-for-Blender) | VRM/VRMA制作 | 骨骼映射、表情预设、VRMA导出、模型修改许可检查 | **制作工具**；不把 Blender/bpy 放进桌面 |
| [MotionEngine](https://github.com/lhupyn/motion-engine) | 动作编排 | pose/mood/action三轨、语义动作目录、可取消等待 | **适配模块**；改写为AIRI AvatarActionDriver |
| [HeadAudio](https://github.com/met4citizen/HeadAudio) | AudioWorklet口型原型 | MFCC/高斯15 viseme和音频工作线程 | **隔离试验**；先修静态问题并比较 wLipSync |
| [TalkingHead](https://github.com/met4citizen/TalkingHead) | Three.js全身角色运行时 | 手势覆盖、姿态/语音协调、retargeter思路 | **参考**；不引入第二 renderer/audio owner |
| [SillyTavern](https://github.com/SillyTavern/SillyTavern) | 角色卡/世界书制作 | PNG角色卡、触发规则、预算和递归思路 | **制作参考**；AGPL，不整拆 |
| [RisuAI](https://github.com/kwaroran/Risuai) | 角色卡/世界书 | lorebook扫描深度、token预算 | **制作参考**；GPL，不整拆 |
| [character-card-spec-v3](https://github.com/kwaroran/character-card-spec-v3) | 格式规范 | CCv3格式说明 | AIRI已有解析，不重复拉 runtime |
| `pixiv/three-vrm`、Live2D SDK、`pixi-live2d-display` | 运行时库 | Airi已有依赖/补丁 | **沿用现有版本**，不覆盖 |
| Rhubarb、uLipSync、Blender Rhubarb插件 | 离线口型/算法参考 | 预制语音 cue、MFCC思路 | 后置；无独立许可的插件不拆 |

VRM Add-on 的源码明确包含 VRMA 导出、跨 rig 映射、mouth/blink/look_at 表情预设和模型修改许可检查；它的许可证是 `MIT OR GPL-3.0-or-later`，角色模型、贴图、音色和样例资产仍要单独审查。交付应是 `.vrm/.vrma + 表情/动作映射 + 资产授权清单`，不是把制作软件打包进 Aimy。

MotionEngine 的 `motions.json`、三轨动作语义和可取消等待可帮助避免让模型直接输出任意骨骼数值，但 `OverlayManager` 直接写 TalkingHead 的骨骼状态，不能原样移植。LLM只能选择已批准动作名、强度和时长，确定性执行器负责模型能力检测、冲突、取消和代次。

HeadAudio 有三个静态风险：package `main` 指向当前树中不存在的 `.min.js`；`if(viseme)` 会忽略编号 0；手动 stop 发 `end` 而主线程只处理 `ended`，可能导致取消后口型不归零。这些尚未运行复现。TalkingHead 是另一个完整 renderer/audio/gesture 所有者，样例模型和 Mixamo 动画也有单独授权，不能整包放进 Aimy。

AIRI 已有 CCv3 schema 和安全解析；角色世界书与用户长期记忆必须分开。角色卡描述“角色是谁”，长期记忆描述“用户确认过什么”，不能用世界书触发器替代来源、确认、纠正和删除。

## 四、其他辅助项目

### Orama、sqlite-vec、Transformers.js

这三者分别是检索、向量扩展和本地模型推理底座，不是完整记忆产品。

- [Orama](https://github.com/oramasearch/orama)，固定 HEAD `b030e1bd1d330327bad1483f2d9c88a9ea0d493c`：有全文/向量/混合检索、过滤、序列化和 `Intl.Segmenter('zh-CN')` 中文分词；Apache-2.0 文件已核对，Node>=20。适合做本地小规模记忆实验，但 update 是先 remove 再 insert，快照落盘不等于事务和崩溃恢复。
- [sqlite-vec](https://github.com/asg017/sqlite-vec)，固定 HEAD `04d28bd21773981e2d266bbf6aa4efbd011eb4f6`：纯 C SQLite 扩展、Node示例、metadata列和KNN，仓库同时保留 Apache-2.0 与 MIT 许可文件；项目注明 pre-v1。适合用现成绑定做对照，不手抄 C，不把向量索引当事实主表。
- [Transformers.js](https://github.com/huggingface/transformers.js)，固定 HEAD `511bb61a7c46b73e33f1af3fb308fbd1afe98c02`：有 feature-extraction、ASR、图像等 pipeline 和本地/远程模型配置；根代码 Apache-2.0，但下载模型和权重另有许可。AIRI 已在 workspace 中使用 Transformers 相关依赖，本轮不建议自动升级到调查到的远端版本。

Orama 和 sqlite-vec 应先二选一。小规模事实可先用确定性 SQLite 表加全文检索；向量召回只有在中文样本证明有帮助时再引入。无论选哪一个，事实来源、确认状态、纠正关系和删除事务都必须由 Aimy 自己维护。

### Promptfoo

[Promptfoo](https://github.com/promptfoo/promptfoo) 固定 HEAD `801428268b5e421b2f6994332f6a06f86b27bb1f`，MIT，当前源码要求 Node>=22.22。自定义 script provider、确定性断言、similarity/JSON检查、取消和 token usage 统计适合做开发验收：同一批中文事实测试写入、召回、纠正、删除、跨进程恢复、人格一致性、模型成本。

它不应进入用户桌面运行包。评测时要关闭遥测、避免缓存掩盖删除/重启缺陷，并把真实模型调用、自动判分和人工体验分别记账。本轮没有用它调用模型。

## 六、建议接入顺序

1. **AIRI 原版基线与主工程手册。** 先确认完整 AIRI 的桌面、会话、音频、角色、图片和授权看屏实际体验；不要让旧样机和新基线形成双运行时。
2. **记忆契约先于记忆框架。** 定义 source message、事实候选、确认、纠正、supersede、删除、重启恢复和异步取消。然后用同一中文数据集比较自管小表、Mem0薄适配、MemOS词法和Hippo RRF。
3. **Smart Turn 局部验证。** 固定模型文件和预处理，在现有 VAD/ASR 旁路测试中文停顿、明确“等等”、附和、游戏声、回声和陈旧结果；不引入 Python 服务。
4. **角色制作与表现。** 先定团队主角色和格式。VRM路径使用 Blender 工具生产资产；Live2D路径继续原SDK。用户确认动作缺口后再适配 MotionEngine。
5. **中文口型与音画协调。** 先测 AIRI wLipSync；有真实缺口才比较 HeadAudio，验证静音/取消归零、时延、中文TTS和模型映射。
6. **观察节奏与成本。** 在 AIRI 授权看屏基础上比较采集频率、理解频率和主动开口频率；N.E.K.O.只贡献代次与预算思路，不带入它的权限和遥测语义。
7. **用 Promptfoo 固定回归。** 把记忆、语音停止、屏幕关闭、角色动作、人格一致性和费用纳入可重复测试；测试通过后再写对应技术手册和实施任务。

顺序不代表已冻结数据库、模型、角色格式或发布方案。用户自建角色、游戏自动操作、外部发信、支付、云同步和持续后台录制仍不在一期范围。

## 七、下一阶段的验收闸门

| 项目 | 通过条件 | 不能用什么替代 |
|---|---|---|
| 记忆 | 新会话/新进程能召回已确认事实；来源可查看；纠正立即替代；删除后检索、生成和重启都不再出现 | README、向量命中、同进程缓存、聊天记录 |
| 连续语音 | 中文自然停顿不抢话；明确插话停止当前播放；陈旧 ASR/LLM/TTS 不污染新轮次 | 模型存在、静态类型检查、英文样例 |
| 看屏 | 只在授权期采集；关闭/隐藏/退出停止并拒绝新调用；理解结果可追溯且不瞎编 | 截图 API 能调用、单帧 demo、持续录制项目 |
| 角色 | 听/想/说/被打断时动作、口型和播放时钟协调；资产许可清楚 | 有 VRM/Live2D 文件、代码 license、演示截图 |
| 开发质量 | 固定数据、成本、缓存和真实模型范围，自动化证据与人工体验分开 | 断言数量、mock、README checkbox |

## 八、调研范围与限制

本轮使用 agent-reach 的 GitHub/`gh` 路由，读取 GitHub repo metadata、默认分支 HEAD、递归 tree、许可证原文件和选定源码；记忆 9 项、多模态 11 项、角色 14 项以及 4 个辅助候选进入证据目录。重点深读范围为记忆4、多模态4、角色4；其余为有界浅查或已有 AIRI 依赖核对，不是逐行正式安全审计。

没有安装依赖、执行下载脚本、调用真实模型、访问麦克风/屏幕/摄像头、读取凭据、修改产品源码、改变 Git 暂存、提交或推送。候选代码、模型、角色、音色、Live2D样例和第三方资产的许可证分别计算；仓库根许可证不能自动覆盖它们。

因此本报告能回答“哪些地方值得拆、哪些需要适配、哪些只在制作/开发侧使用”，不能回答“接入后产品已经可用”。下一步若进入实现，必须先为选定的一项能力编写技术手册、文件边界、数据契约和验收证据，再请求进入代码阶段。
