## 1. 先给结论

1. **那份实时层文档方向曾被误读**：[docs/ryza-airi-realtime-layer-design.md:1](/Users/mima1234/Documents/资料/拆解项目/ryza-ai-revive-master/docs/ryza-airi-realtime-layer-design.md:1) 明写“把 AIRI 的实时交互层移植进 Ryza”，目标是 Ryza 1.2.15。不是把一个已更成熟的新实时栈塞回 AIRI。
2. 当前快照有 Turn/Voice/Stt/Providers/Echo 的运行接线，**没有** `vad.js`、`endpoint.js`、`vision.js`、`proactive.js`、`state_read.js`、`protocol.js`。这些在 [config/layers.json:78](/Users/mima1234/Documents/资料/拆解项目/ryza-ai-revive-master/config/layers.json:78) 标 `planned: true`，原守卫也明确列为未创建。历史 spike 数字只属于来源作者当时环境；本树没有 ONNX/ORT 模型运行资产，不应说已接入。
3. **当前 AIRI 已有真正的 speech-onset 打断链**，因此 Ryza 文档的“airi 没有 barge-in/打断不取消 LLM”在当前 `aimy-app/` 不成立。对照接线详见 §4，不能再复述恢复分支旧结论。
4. 最有价值的是 **带来源的分层记忆策略、表现节奏规则、用户优先/停止一致性测试思路**。记忆与语音实际代码均有隔离复现缺陷，不能原样搬入。AIRI 的音频、provider、窗口、角色渲染、会话生命周期继续沿用。
5. Ryza 桌面实际是 **不透明的 Windows 手机竖栏客户端**。透明/穿透/多屏/自启不能被当成它给 AIRI 补齐的能力；源代码甚至 `transparent: false`。三端共用逻辑不等于跨设备同步。

## 6. 数据流与生命周期

1. **启动**：HTML按script顺序声明全局模块，App.init先同步`_wirePorts()`，再异步hydrate/World/VoiceBank/Sound资源。desktop从稳定`ryza://app/`载入，脚本前把disk JSON塞回localStorage；Android由AssetServer提供同一Web树。共用代码并不共享用户数据，各宿主原点/存储独立；换设备只有手动JSON导入导出，没有云端同步实现。
2. **文字回合**：App.say→Turn.beginTurn stopAll+bump Api epoch→记录用户LongTerm pending→Api组装persona/protocol/cards/facts/scene/history→XHR→parseTaggedReply→App再次检查turn→history/rawlog/Memory/LongTerm + Game.applyDelta/场景副作用→typewriter完成→Turn.speak→可选额外翻译→整句TTS→blob→playSpeech→口型/音频复位。
3. **语音输入**：Stt getUserMedia→PCM ring→RMS能量门→确认onset→Voice opt-in barge→Turn.interrupt；静音300ms→WAV→provider ASR→Voice半双工/冷却/Echo→输入框→可选延迟点击发送。`Voice.stop`关硬件但没有使在飞转写代际失效，且没有清App自动发送计时器。
4. **存储**：localStorage含设置/凭据/档案/日志/记忆/游戏等；desktop镜像明文JSON。音频和服装分别IDB `ryza_voice`、`ryza_crf`；Android原生闹钟另写SharedPreferences `ryza_alarms`。存在三种持久化权威，不是一份“全部数据”。
5. **关闭/隐藏**：desktopclose先flush，最后窗口关闭直接quit；`web-storage` visibilitychange只flush，App visibilitychange只tickTime，未接Voice.stop。Android onPause只是WebView.onPause与foreground=false，没有明确JS采集代际撤销。隐藏/最小化/退出是否彻底停止采集未经真机证明。
6. **存档/删除**：三槽不是事务；LongTerm.export/snapshot不含pending；恢复不撤销inflight归纳；Config.eraseAll只删除`ryza.*`localStorage，IDB与原生闹钟未清。用户自动记忆目标需要独立确认写入、恢复、纠正、删除四种证据，不能拿“有存档按钮”代替。
