# 长期记忆、召回与主动续聊：离线同条件对照与复用顺序

日期：2026-10-14。状态：离线研究验证；不是产品实施、整套应用复现或真实模型体验验收。来源：用户本轮指令及“先完成离线同条件对照”选择、当前AIRI/Aimy固定源码、AionsHome/Ryza固定源码、原模块/SQL/真实浏览器实验。用途：收敛功能缺口、复用范围和分阶段加入顺序。Chromatic继续排除。

## 1. 大白话结论

**AIRI已经能保存聊天、接着同一段历史聊，也有去重、旧轮次拦截和主动事件基础。缺的是把聊天整理成可长期使用的“当前事实”，并可靠地改、删、找回来，再在合适的时候接着聊。**

AionsHome值得借鉴持久画像、来源与版本复查、持久续聊计划；这些具体机制比已核AIRI对应模块更完整。Ryza适合参考记忆条目/卡片组织和管理方式。两者都不能整套当作可靠成品：Aions仍会接受语义错误候选或绕过删除屏障；Ryza更正后会留下两个当前值，删除也可能被旧归纳结果复活。

**召回没有得出“某项目整体更准”的结论。** 有明确日期/关键词/来源回执的实现确实有增量，但自然语言条件提取、同义理解、最终回答正确和主动时机的自然度，本轮都没有真实模型证据。

## 2. 同条件到底控制了什么

- 冻结同一组中文消息、固定抽取候选、32条合成记录、10个查询、10个记忆合同和10个续聊事件场景；统一Asia/Shanghai、2026-10-14 10:00。
- 不用embedding、不调用真实模型；模型位置返回同一固定候选/台词。比较的是候选被怎样存、校验、选取、排队、撤销和提交，不是模型理解力。
- 原函数/原SQL实际执行。允许字段名/时间单位转换、隔离数据库和显式IO替身；不为缺失一方补存储、排序、删除或取消实现。
- top5、1200字符是共同目标，原接口不支持的参数保持unsupported。Aions固定最多10，Ryza原prompt固定12；没有把它们偷偷截成相同数量后宣布公平优胜。
- 同输入不等于接口完全对称：AIRI已核默认链没有同类事实查询API，记录unsupported，不给它造零分检索器，也不把整段历史包含答案算召回成功。
- 新Python进程读取SQLite、新Node进程实例化原内存manager、同浏览器内新页面realm读IndexedDB/localStorage分别标明，不能互称完整应用重启。

## 3. 长期记忆：哪些确实多了，哪些原本就有

| 合同/场景 | AIRI实测范围 | 候选原结果与复用判断 |
|---|---|---|
| 保存与恢复 | 原chatSessionsRepo+真实IndexedDB在页面重建后仍能读取聊天；原task-memory在新Node进程没有事实恢复接口 | Aions原任务写画像，新Python进程读同SQLite能恢复事实；这是具体事实存储增量，不是AIRI聊天丢失 |
| 重复/旧结果 | 原manager精确字符串去重、sourceTurnIndex拒旧均工作 | Aions也有，不重复计新增；优先审用AIRI既有纯规则 |
| 同主题更正 | 原manager只维护字符串列表，无topic/current-fact合同 | Aions相同category/topic替换成乌龙茶并关联U2；Ryza真实浏览器归纳后咖啡/乌龙茶两条active并存。只证明精确主题机制，不证明自动识别同义事实 |
| 来源与在飞修改 | 原manager不读取源消息/版本，不把caller标签当来源证明 | Aions拒不存在的U999、模型等待时源原文被编辑则拒旧候选；适配这些小规则，消费AIRI已持久用户消息 |
| 删除后的旧结果 | 会话删除/tombstone与逐事实遗忘是不同对象；原manager无逐事实ref合同 | Aions同ref拒迟到局部有效，换topic仍能重建；Ryza旧consolidate把已删条目写回真实localStorage，页面重建仍有。原删除全链均不直接搬 |
| 错误含义 | 固定“小说人物→本人姓名”错误候选可写入原manager | Aions有效U1也接受错误候选。来源存在不证明内容蕴含，本轮不评价真实模型一定会误解 |
| 长文本预算 | 原manager同1504字事实输出1540字context；不等于整产品预算 | Aions原600字校验直接拒收、context为空。它没有保住/压缩长事实，不能称总结质量或费用更好 |

LM07/08主任务序列的初始条目由原manual接口建立，native sources为manual；另有自动U1来源的原函数副探针。后者没有把重放结果再提交SQLite，不冒称完整自动删除/重抽取流程都验收。逐层真/假边界在长期记忆证据README和原结果内。

真实浏览器补证还验证了无在飞写入时两方原helper删除后均可读回为空；这个正例与Ryza在飞复活负例同时保留。聊天helper删除整个session，Ryza删除单条entry，不能强行换成相同逐事实合同。

## 4. 召回：能找到证据，但不能冒称更懂用户

用同32条记录分别运行原文输入、fixture控制关键词/日期两臂。Aions执行原命令解析→SQLite查询→排序→格式化及历史来源fallback；Ryza执行原_select与prompt；AIRI执行原上下文组装片段/实际序列化，以及独立原task-memory/notebook。主写者另外运行了完整原core orchestrator的请求投影。

| 例子 | 原结果 | 实际能下的结论 |
|---|---|---|
| “昨天的面试” | Aions原文命令回前天/昨天/今天面试；明确date字段才含正确昨天项，同时带同日背景。Ryza“昨天”给各项统一加分 | 有相对时间窗规则可借，但没证明自然中文路由正确，也不是严格主题纯度更好 |
| “2026-10-12 面试” | Aions明确日期命令含R02，也回同日其他背景；RyzaISO是加权，不是硬过滤 | 日期过滤与日期加权要分开，不只看首条命中就判整套更准 |
| 完全无关的火星问题 | Aions空；Ryza仍按原政策选5条背景，实际prompt为12条 | Aions这一无命中拒回机制有用；Ryza是背景选择器，缺严格不相关拒回策略。未评分模型最终回答 |
| 海岸/海边同义 | Aions无命中；Ryza top5不含海边R07，实际12项背景可能含R07，未测模型如何使用 | 不能把背景偶然包含当语义召回命中，也不能断言最终模型必答错；先做好词法基线，再按真实Bad Case加语义能力 |
| “灯塔约定还有效吗” | Aions控制关键词经历史fallback找到“已经取消”原文；Ryza排retired却未找到取消证据 | 取消原文是相关历史证据，不是复活当前约定。当前事实过滤与历史取证需分开 |
| 2月31日 | Aions明确日期原函数抛ValueError；Ryza无该解析合同，继续选背景 | 不搬原日期异常路径；不据纯函数异常声称整服务崩溃 |

原Q07 gold把retired过滤误当任何历史证据都不得出现，现用单独人工裁定补注纠正，保留冻结fixture与raw结果不重写。旧偏好出现也要先看它是历史证据还是当前事实，不能看见旧正文就判回答错误。部分同日合成created_at晚于clock，本批不评价未来写入保护。

AIRI同32输入的相邻task-memory只保留尾部10条，对不同query格式不变；notebook可存32notes但不自动成为默认事实查询。原core实跑中，同session有咖啡旧原文，新session未自动导入；无关问题仍携带本session全部32条历史。这是合成session port、空额外context、没有附记忆provider时的实际投影，不泛称AIRI所有配置/集成都不支持跨会话记忆。

AIRI另有结构化history-block压缩工具：原函数对32条RawMessage不变；显式结构块可留5条并生成计数说明。计数说明不是事实摘要，源码有工具不等于默认桌面已经自动完成长期事实压缩。

本批短样本回执低于1200字符，不证明最坏预算；也不拿memory-only block和整provider prompt比较费用。

## 5. 主动续聊：AIRI已有主动，缺的是可靠闭环

Aions这次实际跑到原NEXT_CHAT事务→原调度tick/fire/claim→固定生成→原SQLite保存→原ws.broadcast→假WebSocket记录器。AIRI实际跑原notebook→orchestrator→Spark agent→character reaction→Speech记录边缘；没有接真实VoiceKernel、界面或扬声器。记录器收到不等于用户实际听到。

| 场景 | 原结果 | 裁决 |
|---|---|---|
| 两分钟后续聊 | Aions到120秒建立一次原保存/广播；AIRI可原生scheduleTask，但未接NEXT_CHAT规划协议 | 持久计划语义可借鉴，AIRI已有主动链继续保留 |
| 重复领取与进程恢复 | Aions两个新OS进程共用隔离SQLite，第二进程一次提交，再fire不再领取；AIRI原内存task新进程为空 | Aions持久/单次领取局部更完整；不是崩溃时发声恰好一次证明 |
| 用户在领取前回来 | Aions原broadcast hook撤销未领取计划；AIRI该task模块无同类新消息取消输入 | Aions这个保护有用；AIRI记unsupported，不冒充执行不存在的cancel API |
| 关闭开关、生成中回来/关闭 | Aions完整原链仍写入与广播；AIRI没有同类主动toggle，新消息撤销也无原生输入；生成中映射原dispose仍有旧reaction/记录器提交 | 两方都不能原样满足本期最终取消合同。dispose是生命周期控制，不与toggle混成同API |
| 切会话 | Aions触发时取最新私聊，AIRIcharacter生成时取activeSessionId，旧计划均能进conv-B记录器 | 本期续聊需绑定原会话/事件版本；不宣称它们原全局提醒设计承诺该绑定 |
| 同一AIRI提醒多次生成 | normal priority、dueAt+120秒，原60秒窗口/soon10秒机制在70/100/130秒生成 | 不满足本轮“严格两分钟后、单次续聊”合同；这是原提醒政策，不称上游bug或自然度更差 |
| idle原caller | 领取前关闭或用户回归会拦截；固定JSON生成await期间发生变化则仍可提交 | 不能沿旧helper笼统说完全没有保护；补的是等待后/提交前重验 |

PR09的十案例原结果保持inconclusive，另附独立补证：同32记录、无embedding，原build_surfacing_memories和原build_memory_blocks实际返回并组装8条近期背景；skip_digest则不调用生产者。它证明请求背景取材，不证明后台自主发言。该共享builder是群聊消费路径；私聊原caller直接调用生产者并插入history，本轮仅源码核对，未运行完整私聊。没有强迫unresolved或语义向量正分支通过，近期补满也不等于相关性更好。

**可取的增量是持久事件和单次领取思路；必须补会话/epoch绑定、在飞失效、提交前重验、静默与预算。** 用户主动聊天时顺口想起相关记忆、后台自己发起话题，是两个场景。先验证前者，再开放后者；不把“背景浮现”字段或定时器能响当作会自然关心用户。

## 6. 推荐分阶段加入Aimy的顺序

| 阶段 | 用户能得到什么 | 复用/保留什么 | 进入下一阶段的门槛 |
|---|---|---|---|
| 0 收尾现有基线 | 原桌面品牌、本地数据边界与退出/取消行为稳定 | 继续AIRI唯一会话、音频、角色与存储owner；不把工程收尾算外部新功能 | 原功能与本地/生命周期回归，不改本轮产品代码 |
| 1 记得住，也改得掉 | 自动保存小量明确当前事实，能看来源、更正、删除，跨会话/重启恢复 | AIRI既有持久聊天/ID/去重/轮次规则；适配Aions来源复查、精确事实更新、任务版本门。参考Ryza条目/卡片管理 | 写入→新进程→更正→删除→迟到/重试均逐项验证；来源有效不冒充语义正确 |
| 2 找得对，用得少 | 根据当前问题选有效事实，需要时取历史证据；用户聊天时自然带出相关回忆 | 适配日期/词法/来源回执规则，分离current-fact和historical-evidence。Aimy统一整条预算/无关拒回 | 固定查询同条件复测；有来源、无关不硬塞、旧事实不当当前、非法日期不坏链；不先上复杂向量栈 |
| 3 再主动接着聊 | 记得未完事项，允许轻主动后有持久计划、静默/冷却/预算，用户回来即失效 | AIRI Spark/呈现链保留；参考Aions持久事件/领取机制，补生成中/提交前session与epoch重验 | 待执行、生成中、提交前、重启/重复/切会话全部验证；不能把claim去重当发声恰好一次 |
| 4 真实模型与体验 | 验证是否理解否定、记错本人、自然想起、会不会打扰 | 对同一用户场景、同模型/Prompt/预算试跑；修Bad Case再决定语义检索、摘要/日历压缩等 | 本轮用户选离线，因此这些尚未执行；不能以固定候选测试替代 |

日历压缩/复杂分层保留在事实与删除稳定后再做，不先用摘要遮住丢事实/复活问题。OLV独立译播/区域权重动作仍是条件候选；Kirara两个机制后置，Charakuru为生产侧工具；本轮没有扩大一期需求、接口或任务数量。

## 7. 交付与完成边界

当前结论可以说：具体事实管理和持久计划存在缺口；候选若干小机制更完整且有原代码执行证据；不能说整体记忆、召回质量或主动体验已经胜过AIRI。

本轮用户选择离线：真实模型、自然度、真人长期使用、完整Electron事实仓库与新代码功能端到端均未验。所有新增测试写在隔离/tmp，正式文档写根docs；不改产品/参考源码、依赖或Git暂存，不接第二套运行时。
