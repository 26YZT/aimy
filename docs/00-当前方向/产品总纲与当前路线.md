## 1. 产品究竟帮助用户完成什么

用户在电脑前想倾诉、想有人一起看视频或玩游戏时，可以打开一个看得见、能交流、理解获准共享情境、记得相处经历的伴侣；需要专注或结束时，她能安静下来，之后还能可靠接着使用。

当前对象是创作者本人，随后少量受邀用户，macOS、本地优先、BYOK、一个主要角色。尚没有真实用户研究证明广泛人群的留存、付费意愿或市场规模；用户明确需求足以指导个人版本，不冒充市场验证。

第一性原理下，有四个相互支撑的结果：

| 用户得到的结果 | 需要的能力 | 不能用什么代替证明 |
|---|---|---|
| 愿意和她相处 | 自然中文、温柔有主见、接住当下情绪、角色分寸 | 仅写好人格Prompt或答对事实 |
| 她能陪在当前活动里 | 桌面存在感、文字/图片/连续语音、角色协调、授权后的当前情境理解 | 单个模块存在、角色能加载、能识别一帧 |
| 相处能延续 | 有来源的记忆、变化更新、相关时自然想起、跨会话/重启 | 聊天记录留存、存储测试通过、机械复述 |
| 用户放心并能掌控 | 本地边界、授权与停止、费用可控、纠正/移除有效、可靠退出恢复 | 按钮显示关闭、默认设置、文档检查数量 |

记忆是已选首批重点，解决第三项，也支撑第一项；它不能独自代表整个陪伴产品。

## 2. 已经确定的产品边界

- 直接沿用 `aimy-app/` 内已继承的AIRI完整代码，桌面入口 `apps/stage-tamagotchi/`；旧 `digital-lover` 样机仅作历史参考。R1主工程继承已经完成，不重迁移/重造桌面与聊天框架。
- 保留原版界面/角色/语音等主链，按缺口增量。品牌是必要收尾，不能替代真实使用；正式人物资源与音色仍待具体候选。
- 温柔自然、有主见，能安慰、开玩笑和适度拌嘴；初始亲密伴侣。关系连续不靠伪造共同过去，首批没有关系数值经济或签到系统。
- 首次先配模型，再填可跳过资料；自动记忆默认开并简短说明，可暂停。只处理启用后的新聊天，恢复不补暂停期间；资料/记忆本地保存，可调用用户配置的云模型，不额外同步Aimy云端。
- 记忆模型默认跟随聊天，可独立指定；“关于我”默认查看，维护操作折叠；关联判断由产品负责，不能让使用者裁定，也不能连坐删除同源独立事实。
- 收起聊天仍可见角色；隐藏/最小化/退出与收起语义分开。麦克风与看屏独立授权、默认关闭，撤权后停止采集并拒绝晚到结果。
- 首批自动记忆/管理/正常聊天相关回忆；后台主动续聊已在10月18日本轮获准有界接入，默认关闭。无摄像头、电脑代操作、外发、支付；保留既有未成年人基础保护与危机兜底。
- 文字记忆验收保留用户8例V2，固定DeepSeek官方deepseek-flash，同条件对照，¥10一次总额；助手先执行并整理，用户实际试聊。角色/音色/视觉模型与全产品设备预算不由这一选择自动决定。

完整选择看[逐项审定记录](../05-实施手册/2026-10-14-Aimy增量开发交接包/首批审定稿-v1/逐项审定记录.md)。第6题已按用户更正撤回；第8题原回复是澄清请求，随后用户已明确“好的开始开发”。现按已定首批范围实施。

## 3. 当前完整体验地图

“源码已有”“当时运行过”“当前体验通过”分别记录。下表依据已有证据与本轮源码/文档核对，最新运行结果另见首批实现与窗口复测，原基础和验收范围不混算。

| 体验 | AIRI已有基础与旧证据 | 当前仍需证明 | 本批/后续位置 |
|---|---|---|---|
| 打开、配置并开始聊天 | R1 A1–A9有10-12记录，Live2D示例与一轮中文文字曾通过 | 当前环境/独立profile、首次流程、本地配置/退出 | 早期基线；品牌局部收尾 |
| 日常倾诉与人格连续 | 原chat/角色卡可沿用，性格方向已选 | 真实长对话、情绪分寸、适度玩笑/不同意见 | 当前体验基线与首批试聊都观察 |
| 图片交流 | 原图像消息和视觉链已有 | 当前实际图片理解、延迟与错误表达 | 现有能力复验；不重造视觉框架 |
| 中文语音与插话 | ASR/TTS/VAD、静音回执、回声门控已有接线 | 真设备、外放/耳机、游戏背景音、误打断、上下文衔接 | 早了解基线；优化按实测排，不固定等后台续聊后 |
| 人物有回应、声画协调 | 多渲染器、口型、动作/表情、待机已有；示例曾显示 | 倾听/等待/说话/打断状态协调，具体角色/声音效果 | 示例先验状态；正式资产单独审定 |
| 收起聊天继续陪伴 | 多窗口与角色系统已继承 | 真收起、失焦、隐藏/最小化的动画/声音/采集行为 | 基线与LIFE回归；close→hide不能替代验证 |
| 记忆与自然回忆 | 聊天持久/压缩、task-memory相邻规则已有 | 默认桌面持久事实/来源/纠正删除/恢复/含蓄召回闭环 | 首批已接入，10月16日真实8例暂未通过；本轮不覆盖该失败 |
| 记忆维护不让用户操心 | 原记忆页WIP；当前交互已选 | 自动处理依赖、保留独立事实、真实回执 | 首批；这是产品责任，不再问技术判断题 |
| 一起看视频/玩游戏 | 原授权取帧/队列/上下文、间隔统计已有 | 完整组合场景的时机、相关性、抢话、过时画面与费用 | 全产品核心旅程；看屏新入口后批，不因后置就不记录现状 |
| 合适的主动关心 | AIRI Spark/内存任务已有，候选持久计划有局部证据 | 重启、取消、防打扰、时机与真实合适性 | 本轮已接入持久计划与保护，真实时机/自然度仍待验 |
| 放心停止与下次恢复 | 原权限、退出、IndexedDB链已有 | 当前真正停止、实际进程退出、跨进程恢复、无额外同步 | 启用相关功能前的硬门，不能靠mock盖章 |
| 可供受邀者安装使用 | builder/updater与品牌基础已有 | 正式资产/声音许可、包/更新源、干净安装与使用证据 | 分发前另验；首批记忆通过不是发行批准 |

核心“陪玩/陪看”必须作为组合旅程看：打开→文字/语音交流→自愿共享示例窗口→对当前内容回应→用户插话/收起聊天→安静/停止观察→退出与恢复。无法使用的环节标未测/待增量，不能拼接几个单模块的通过冒称完整体验成立。

## 4. 五个复用项目分别服务什么

复用的判断顺序是：用户结果 → AIRI具体缺口 → 候选有证据的差异 → 适配代价/边界 → 同条件体验。项目名和功能数量不能反过来定义产品。

| 项目 | 当前合理用途 | 重开/继续条件 |
|---|---|---|
| AionsHome | 前批记忆规则；本轮计划、回顾来源、语音导演与收尾规则 | 适配原实现反例，保持单一AIRI运行权威；真实收益未证明 |
| Ryza | 前批筛选；本轮条目分层组织、回声、动作避免重复方法 | 不搬其存储/归纳器/角色；回顾不是模型总结 |
| Open-LLM-VTuber | 本轮独立译播方法与区域权重动作行为 | 后台MIT方法有界适配；受限前端独立实现，正式音色/动作质量待验 |
| kirara-ai | 本轮有限本地组合规则与类型图行为参考 | 独立TS实现；无第二后端、通用图编辑器或外部IM发送 |
| Charakuru | 本轮VRM导入检查与交接报告方法 | 无Kit/远端角色生成；所有AIRI格式保留；正式角色/视觉质量另验 |

Chromatic退出候选；AIRI现有依赖本轮不因这条决定被移除。原源代码、运行时、模型/角色/音声资源的许可边界分别核对。五个项目都考虑过，不要求每个都往产品装一遍。

## 5. 纠偏后的开发与学习节奏

四阶段方法保持：**AIRI原版主工程 → 拆解/选择增量并倒推手册 → 分阶段实现 → 体验迭代**。R1已完成。当前首批选择不变；新增以下“何时能看到结果”的检查点，不把一张局部任务表当全产品路线。

| 检查点 | 看见/学到什么 | 必须满足的边界 |
|---|---|---|
| G0 现成陪伴基线 | 当前AIRI文字/角色/窗口/历史到底能用到哪一步，语音/图片/看屏哪些未验 | 获实施/运行授权，独立合成profile，实际可达的本地/采集/退出门先成立；未通过功能不启用、不宣称可用。可以先展示受控基线，不等新增记忆全部完成 |
| G1 最小完整记忆链 | 来源→可靠保存→更新/移除→实际召回payload→回答是否使用，尽早发现“含蓄说法想不起”的问题 | 在真实启用前补来源/持久回执/取消删除/最终发送/费用保护；工程及评测阶段条件满足后，优先跑现有8例中的高风险情景；不加第9个用户故事或另增预算 |
| G2 首批完整交付 | 初始资料、关于我、模型覆盖、全部8例和真实重启/多窗/负例闭合 | 全首批硬门和最终对照仍要完成；中间演示不代替验收；助手先跑、用户再试聊 |
| G3 按体验选后批 | 哪个问题最妨碍“愿意让她陪着” | 本轮已批准续聊、语音、互动、规则和检查的有界增量；后续按真实阻断/频率/改善价值，不机械按项目名单 |

技术依赖与交付门分开：纯叶子规则/契约可先离线验证；本地同步/密钥、来源与真正取消是启用真实链的前置。所有可达采集入口都受控；未启用的入口也要有确定性拒绝和无旁路证据，不能靠“不打开页面”省保护。

首批仍沿9个任务ID和既有文件边界，保留一个共享区主写者。[阶段展示与启用门](../05-实施手册/2026-10-14-Aimy增量开发交接包/首批审定稿-v1/05-任务文件边界与实施顺序.md)补充早期反馈。118文件是审定时的提案清单，实际同功能消费链补线和文件合并已逐项留在首批实现映射；不按文件数量汇报完成度。

¥10费用约束不能删；早期内部验证先核现有受控harness能否覆盖每次真实HTTP/重试/有限输出/共同账本，证据不足则保留既定host桥。不得先冻结一个未经验证的新替代架构，也不把验收额度做成普通用户日/月产品配额。

## 6. 优先级如何判断

先解决实际数据/权限/费用与退出风险；再看是否阻断核心使用、出现频率和用户感受，再看收益证据、改动代价与可逆性。已有能力的坏体验优先复现，不因外部项目有一个新模块就替换整条链。

记忆目前被用户明确选为首批，应完成；与此同时，完整体验地图不能消失。后批不是必须按项目名单依次做。正式角色/音色不锁定时，可用明确标为测试示例的资源验证状态协调；这不代表正式外观已被接受。

每次展示同时报告：**本批能力证据、全产品体验状态、本人是否愿意继续用**。不把“8例过了”“55条审核”“90帧物理”合成产品成功率。定量阈值须基于实际记录校准，本轮不编留存/转化/满意度数字，也不新增云端行为跟踪。
