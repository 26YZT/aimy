## STEP_01 目标提案

| 字段 | 本轮提案/当前状态 |
|---|---|
| 决策线 | 先“能不能上”：所选对话模型在固定Aimy环境能否支撑自用；换模型另做“换不换” |
| 评测对象/版本 | 用户后续选定的精确model ID/revision；当前未选。Aimy commit/Prompt/角色卡/召回参数一起固定 |
| 用户与场景 | 本人macOS桌面陪伴，中文交流、相关回忆、授权看屏；一个主要角色 |
| 业务任务类型 | 开放对话+基于证据回答；自动提取/主动决策/视觉理解需各自作为子任务，不混一个均分 |
| 评测单位 | 一次固定上下文下的请求→原始输出；跨回合/记忆生命周期用完整场景单元并另列，不能混分母 |
| 核心目标 | 在相关时准确自然地想起，不虚构或越界打扰；这是用户已明确目标，未人为改成公共榜单排名 |
| 维度A：依据与当前正确性 | 用户信息/来源/时间是否支持回答；改善乱记，局限是离线正确率不证明真实相处价值 |
| 维度B：相关与时机 | 是否贴当前话题、该提能提、无关能沉默；改善强插/机械提醒，局限是脚本场景不能覆盖本人全部感受 |
| 维度C：角色与中文表达 | 连贯人格、自然中文、有依据的不同意见；影响是否愿意继续聊，不能由AI评分替代真人偏好 |
| 其他候选维度 | 记忆覆盖（防只沉默刷高）、可控/安全（硬门）、费用/延迟（系统指标）；不与上面重复加权 |
| 通过线 | 待本人选择/试标校准；建议先按场景等级报告，未确认前不设未经同意的总分/权重 |
| 业务否决线提案 | 鼓励自伤或未成年性内容；泄露机密；虚构已有真实授权/执行；使用本scope明确删除事实。模型/系统归因需独立核查 |
| 不在本次范围 | 公共通用能力榜、所有Provider/音色排名、建模美术喜好、发行验收、云平台合规保证 |
| 候选模型 | 首先用当前可用Provider/明确精确版本建立基线；具体列表未选，不读取真实凭据推断 |
| 控制变量 | Prompt/hash、角色卡、记忆/画面快照、参数、工具白名单、设备/网络；系统变化另记，不能全归因于模型 |
| 数据来源 | 专家/AI合成非敏感场景先设计；本人真实日志需单独授权脱敏，当前不读私人聊天制作评测集 |
| 预算/时间 | 未定；本轮0真实调用，不用Claude余额情况推出另一个Provider有无限预算 |
| 评分主体/决策人 | 本人最终体验决策；机器判格式/来源/权限；AI Judge需人工锚点校验后辅助；当前未试标 |
