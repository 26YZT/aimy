# Aimy 开发顺序与交付闭环独立审查

日期：2026-10-15，Asia/Shanghai。状态：只读审查建议；未授权新实现或新架构。范围：当前入口/方向、R1–R3、首批03–06/追溯/118文件边界及必要AIRI源码。未启动、构建、调用模型、读取真实数据或凭据；未改产品或根docs。

## 结论

产品底座没有走偏：AIRI完整源码已经成为aimy-app，桌面/角色/聊天/Provider/本地聊天保存都有可沿用链。首批选记忆是用户已定优先级，不是错误。当前真正的风险是**首批记忆工程计划正在承担整个产品的唯一路线，个人完整试用放在最后EXP，缺少更早的原版陪伴基线体验里程碑**。中间已有逐任务测试、品牌/UI截图，并非完全无反馈；但它们仍未回答“当前Aimy作为陪伴产品究竟好不好用”。

118文件是上限，不足以证明过度设计；不要为了数量好看删除必要保护。问题应按“每一步新增什么用户价值、最便宜的未知如何验证、该保护在哪条实际可达链必需”判断。建议保留既定首批范围与硬门，把强串行改为依赖明确、可逐步看见的交付里程碑。

## 发现（P1为实施前应改正的方向/计划问题；P2为接续可靠性问题）

### E1 / P1：首批计划覆盖了原本独立的“先体验AIRI”环节

- 证据：`docs/00-当前方向/开发方向与边界.md:7–9,37–39`定义陪伴游戏/视频/日常交流与快速分批；旧体验输入`docs/00-当前方向/PRD-2.0-对齐草案.md:20–26,68–72`明确可用基线和真实体验先行。新`首批审定稿-v1/05-任务文件边界与实施顺序.md:7,17–25`将BASE到EXP九项全串行；`docs/任务编排.md:3`称后续仅按本稿九任务。新`06-验收与评测目标.md:12,71,87–99`对首批试用设硬门、但没有独立“原有可用陪伴基线”里程碑。
- 影响：记忆作为近期增量合理，却可能被下一模型当作全产品唯一目标。原有文字/角色/图片/语音/窗口体验的实际状态只保留在旧R3，缺少现在的排程入口。
- 最小修正：总路线明确“继承体验基线”和“首批记忆增量”是两类证据；补当前体验状态表（可见角色、中文文字、图片、声音/打断、收起聊天、恢复/退出、看屏），每项标已有证据/待测/下一交付。首批记忆8例继续保留，不能用其完成代替全产品完成。
- 待验证：R1之后当前可执行产物和环境是否仍可复现中文文字/角色；本轮未启动。不能把10-12截图作为10-15整机新通过。

### E2 / P1：工程未知与产品价值未知的验证顺序不平衡

- 证据：`03-技术与数据契约.md:92`仍承认词法/日期无法证明“忘了重要事情”“那个小家伙”等含蓄召回；`06-验收与评测目标.md:57–59,65–67`明确8例语义/自然度未证明；`05-任务文件边界与实施顺序.md:22–25`把0真实模型MEM-02、完整MEM-03/INT之后才EXP。
- 影响：先完成全部页面/边界再验证最不确定的召回价值，可能晚发现选定词法策略不够。继续完善来源血缘不能自动解决“用户换个说法时能不能想起”。
- 最小修正：实施获准且评测阶段条件满足后，用已保留的8例中最高风险情景尽早做工程人员的内部验证（例如近期生日/布丁指代）；先完成最小可观察的保存→召回payload→生成链，依然有来源、持久回执、删除/取消/费用硬门，再扩大完整8例。它不替代最终8例，不新增用户故事、不另选模型、不另增预算，不把中间演示当用户验收；此时仅提议次序，不调用模型。
- 待验证：是否真的需要比现词法更强的召回机制；不能在未测前自动加向量库/RAG服务或宣布更强。

### E3 / P1：任务依赖和交付质量门混为一条全串行链

## 建议的最小分阶段验证（非新开工授权）

1. **先核清现在的Aimy**：依原R1来源和当前独立profile/环境，待实施授权后建立受控桌面基线。最低本地网络/密钥/退出保护满足后，显示现有角色、文字对话、图片/历史和收起窗口；尚未可靠的功能禁止启用或如实标待验。不会因为早期体验而省掉任何实际可达路径的保护；不把旧用户数据带来。
2. **再证明一个完整记忆闭环**：仍基于AIRI原owner/Provider/IDB，选定Aions/Ryza规则先在有来源/持久回执/取消删除门的实际链中落地；查保存内容、真正发送的召回payload、回复是否使用。关键含蓄语义在既定阶段/预算获准后尽早看证据，尚不交用户正式验收。
3. **扩齐已承诺首批**：初始资料/关于我/模型覆盖/所有8例、真实退出重启、多窗、源变更/删除与迟到任务；所有首批工程硬门闭合后，助手完成8例AIRI对照，再交用户试聊，维持既定分工。
4. **持续保留全产品体验清单**：声音、插话、角色协同、授权看屏、后台主动、正式资产分别记录基线与下一触发条件；后批按真实高频缺口推进，不因记忆通过就默认全部已完成。

这只是将验证次序和交付边界拆清；已定模型、8例、¥10、初始伴侣/性格、本地优先、默认记忆及维护行为不重新选。正式代码授权仍未获得，本轮不实施。
