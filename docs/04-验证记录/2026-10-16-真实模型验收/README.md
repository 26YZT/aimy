# 首批8例真实模型验收

日期：2026-10-16（Asia/Shanghai）。状态：已完成本轮实际尝试、一次面试复测和证据核对；首批记忆验收未通过，不作为发布通过结论。来源：固定受控构建、用户V2原文、正式单账本、真实模型回复和失败测试资料的只读恢复。没有修改产品代码来改善本轮成绩。

## 结论

Aimy已经能提取、落盘并在部分场景使用长期记忆，但“存对→选中→准确表达”的链路不稳定，不能宣布整体优于原AIRI。布丁案例有跨会话使用旧信息的实际证据；慢慢来案例则明确展示“已经存下，但没有召回”。面试整理重复失败、生日日期错误、人设和语言混杂仍阻碍首批通过。

## 费用与执行完整性

56次真实请求全部settled，无unknown、无预留未结算、无预算暂停。按预先核验的官方高峰费率保守核算共¥0.206679，保守剩余额度¥9.793321。含首轮失败及面试的一次复测，不是查询平台账户得出的实际扣款。[费用审计](cost-audit.json)保留分臂调用与token数。原AIRI20次；Aimy36次（18次聊天、18次整理）。

8个案例两臂均尝试。Aimy的1–4、6、8完成全流程，5和7未完成；面试案例再试一次仍失败。原AIRI8例均有结果，面试另有一次复测。**不得把6例走完工程流程称为6例语义合格。** 没有为了凑齐结果清除失败或重置账本。

## 同条件范围与局限

- 同8例原话、DeepSeek官方deepseek-flash、非思考、最多2048输出token，未设不同temperature/top_p；相同工具禁用和费用保护。每case每臂独立资料；未把预期答案喂给模型。
- 原AIRI固定继承基线，Aimy固定当前产物；精确产物绑定和执行前审阅方法见[执行记录](execution-plan.json)，56个实际请求参数见[输入核对](request-control-audit.json)。模型实际回执标识deepseek-flash；服务商内部不可变模型修订未单独取得。
- 两臂基础角色相同，但Aimy保留已实现的额外陪伴提示和记忆提示。因此这是**完整首批增量与原版的对照，不是仅开关记忆的纯消融实验**；不能将语气/语言差异单独归因记忆。未伪称完整系统提示逐字相同。
- 1–6保留同会话历史；5按计划重启原进程再恢复同会话。只有7、8主动换新会话，较直接检验长期记忆。Aimy案例5因首轮整理失败，实际未进入重启环节。
- 注入了会话时钟，但实际聊天请求未清楚提供当前本地日期；整理请求给出数值时间戳，模型日期换算又出错。生日结果不能简单归因“模型不懂日期”，还暴露时间上下文设计缺口。
- 本助手按用户原期待与禁止项非盲审阅，无外部Judge调用、无独立人工校准；单轮为主，未评估稳定性或统计显著性。下表为证据判读，不是已批准权重的综合评分。

## 三个关键证据链

1. **布丁：确有回忆作用，但不能算全例通过。** Aimy首轮事实库记录猫名、橘猫、两个月、去年去世；新会话实际发出的system包含该记忆。用户新输入没提旧照片，回复却说“你说不太敢认真看旧照片”“能和它一起生活那么多年”，与原AIRI追问名字不同。不过首轮回复把“两个月”说成“两岁”，后续整理还失败。原始末轮回复通过失败case的IndexedDB副本只读恢复，不是补跑或编写。
2. **慢慢来：存储成功、召回缺失。** 事实库存有咖啡馆名字、树、便签墙和未实现梦想；第二轮新会话请求没有这条证据。回复只泛聊小店，没有接上梦想。当前词面相关筛选对“咖啡馆/咖啡店”等表达变化是否稳健需重点修正；本轮可确认漏选，具体哪条打分规则造成仍需定向回归。
3. **日期：既有语义表达错误，也有结构化数据错误。** 生日目标10月20日；Aimy保存dueAt=1792651200000，按Asia/Shanghai换算为10月22日14:40。后续10月19日又被说成周日。面试两次整理均有持久失败码INVALID_INPUT，原始模型整理输出未被完整保存，不能凭错误码断言是哪一个字段有误。

## 建议改进顺序

1. **先修整理可靠性和时间。** 给模型可执行的结构约束，正确处理空结果/可选字段；校验失败保留不含密钥的可诊断信息，有限重试仍受同账本控制。由代码按明确日期/时区转换与核验时间，向聊天模型提供清楚的当前日期。不能用猜出来的毫秒时间戳直接当可靠日程。
2. **再修相关召回。** 先用现有8例及表达变体做不花模型费的回归，确保已存梦想在咖啡话题下能被选中。再判断是否需要语义检索，不能只凭本轮就决定上重型RAG或另换一套记忆后端。
3. **收敛人设与对话分寸。** 原版“English anime/VTuber、实验室、AIRI”设定仍在，追加Aimy中文陪伴提示没有消除冲突；出现中英混用、自称AIRI。应明确中文交流、统一角色，用户转话题时立即跟随；不要把愿意安慰等同继续追问旧伤。
4. 修复后沿原8例和**剩余同一预算**复测，失败前后版本分别留存，再由用户实际试聊。后台主动续聊继续后置。
