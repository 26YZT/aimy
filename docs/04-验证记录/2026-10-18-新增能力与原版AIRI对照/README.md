## 四个容易误读的地方

1. **主动链的比较针对单次续聊合同。** 原版是通用提醒系统，允许提前和重复，并可由任务管理标记完成。本轮固定模型只回文本，工具builder为明确空边界；不能据此推断真实原版永远重复说话。新增方案的差异是程序直接保证本次领取/交付，不依赖模型结束任务。
2. **“持久化”不等于“退出后必定再提醒”。** 当前原版新进程测试无内存任务；当前Aimy浏览器新repository仍读到同IndexedDB计划。后者本轮不是新OS进程。Aimy正常退出会撤销计划，因此不能把它介绍成重开闹钟。上次原生重启验的是设置，不是这次计划。
3. **新增检查能约束新风险，未必改善原有输出。** 导演的台词校验有用，但原版直接读原文也不会产生导演改词风险。仅用“能拒绝坏导演结果”证明整体比原版更强是不成立的。
4. **负面观察不自动变成代码修复授权。** 本轮保留短句断段、重复话语草稿、动作仍可能重复、错译未语义拦截的结果，没有改阈值、加模型或重新打包让结果看起来更好。

## 怎样体验比较合理

- 优先看续聊的可控性、Live2D点击配置、VRM检查和保存失败提示，收益最具体。
- 有多语言朗读需求时再开译播；先观察翻译、等待和费用，再决定是否常开。
- 短句收尾和回声保护按设备/习惯选择，不能默认“开了就更好”。这轮保持原默认关闭。
- 表达导演先保留为待证选项：需要与原直接SSML设置做同音色盲听，并比较额外延时/费用，才能判断是否值得继续。
- 回顾/本地规则是组织和配置便利，不向用户承诺记忆更准、角色更懂人。
