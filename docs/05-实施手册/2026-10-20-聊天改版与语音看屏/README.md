# 聊天改版、看屏入口、钥匙串与MiMo语音

日期：2026-10-20。状态：用户本轮明确要求改进四项体验，文档先于本轮代码实施。来源：用户六张截图、用户确认的Safe Storage弹窗/MiMo服务、当前 `.5` 实现及10月18日后续验证。用途：约束本轮实施与验收。此前累计清单只读边界由本轮明确新需求替代；旧数据、凭据、费用和单运行主链边界继续有效。

## 用户能看到的结果

1. 聊天界面按用户提供的微信布局组织为“聊天、角色、我”。保留Aimy品牌与桌面人物。聊天有会话列表、双方头像、清楚的气泡和输入栏；角色入口使用原角色卡，选择后沿原激活/会话逻辑；“我”汇集用户资料和现有设置。
2. 聊天和人物侧栏有共享入口。第一次选择屏幕/窗口并满足系统权限；开始后同时运行原视觉识别并给聊天提供当前画面描述。停止时停止采集/推理并撤销旧画面。收起聊天与隐藏人物分别处理。
3. “陪我看游戏”是同一共享链的关注模式，不另开采集；不控制键鼠，不把Minecraft/Factorio独立机器人当作看屏功能。
4. 减少钥匙串反复申请：实例缓存命中不重复解密，显示“已保存”不解密，失败后暂停后台连试。只有用户主动重试才解除失败暂停。不改明文保存，不删除Keychain项或放宽给所有程序。
5. 在原音频owner内使用MiMo内置音色的原生流式能力，修TTS取消透传，提供无需额外导演模型的自然语气建议。减少不必要碎段要保留早开口/可打断与长段上限；不声称已经达到GPT听感。

## 原链与不变边界

主工程仍是 `aimy-app`，桌面仍是 `stage-tamagotchi`。聊天/历史/角色/Provider/录音/播放/权限/持久化都用原owner。没有新聊天数据库、复制会话、读取真实密钥或第二音频运行时。不修改既有私人资料来制作UI样例。截图只作布局参考，不把真实微信联系人、头像、聊天、微信号复制到代码或测试。

除固定源文件/实现记录外，合成测试放 `/tmp/aimy-oct20`。本轮不挪用8例记忆预算，不因服务文档写免费就自动发请求。真实模型/音频效果的测试条件另外明确，离线流式和取消通过不能冒充人类听感通过。

用户已经给出具体视觉目标并要求改造。本轮在原架构内直接实现，不另建三套候选架构或要求重复批准已说清的需求。跨供应商原生实时语音、稳定Developer ID证书购买、Keychain授权规则更改、数据迁移均不在当前实现内。
