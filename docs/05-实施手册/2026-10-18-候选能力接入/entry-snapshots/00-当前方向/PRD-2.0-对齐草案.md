## 1. 要做成的体验

用户孤独、想倾诉或想有人一起玩游戏、看视频时打开 Aimy，就能见到一个有声音、有动作、记得彼此经历的伴侣。角色能接住用户的文字和话语，在授权范围内理解正在发生的事情，作出相关、自然、及时的回应。

默认关系定位是伴侣。温柔支持、活泼拌嘴和有依据的不同意见可以共存。关系成长作为相处的点睛之笔，阶段或好感数字不主导使用流程。

**保留 AIRI 原版桌面 UI、交互与角色系统，再补足体验缺口。** 不重新制作一套简化界面，不把另一个框架的演示直接当作产品完成。

第一版先完成原版继承、名称/品牌和必要界面定制，让用户直接体验 Aimy。页面布局和交互以原版为起点，进一步外观调整及功能优化根据使用反馈安排。可靠记忆和自然语音的增量实验，不再作为交付这版应用的前置大工程。

## 2. 已明确的体验要求

| ID | 用户希望看到的结果 | 验收方式与现有差距 |
|---|---|---|
| P20-01 | 打开就能看到、听到并与伴侣交流 | 沿用原版角色与聊天流程；文字实测通过，中文语音和声音自然度待验 |
| P20-02 | 收起主要聊天界面后，桌面角色继续动作和语音互动 | 原版可折叠聊天；源码显示真正minimize会令stagePaused=true，实际最小化及后台声音尚未验收。具体窗口语义待答 |
| P20-03 | 说话、倾听、等待时都有自然表现 | 检查口型、表情、动作与语音协调，插话后转为倾听且待机不冻结；源码能力不能代替体验验收 |
| P20-04 | 用户有效插话后停止旧回复，听完再接着回答 | 新回答综合此前对话、已说内容和新输入；记录播放停止耗时、已说/未说边界、上下文连续与旧输出回流；拒绝回声、附和、噪声引发的误打断 |
| P20-05 | 记得称呼、偏好、烦恼、共同聊过的事 | 同轮、跨会话、退出重启、长历史/换说法分别验证；聊天记录保存不能代替事实召回 |
| P20-06 | 记忆可纠正、可删除，变化事实不会被旧印象覆盖 | 纠正后新会话/重启验证；删除覆盖检索、派生摘要和回答使用，不能因重启或再次提取旧聊天而复活；具体存储清理范围须说明 |
| P20-07 | 人格连续，能共鸣、吐槽、讨论剧情或提供攻略 | 用固定场景评审相关性、语气与角色一致性；不把所有反应简化成情绪标签 |
| P20-08 | 可以表达不同意见，并有可解释依据和频次约束 | 对记忆/此前对话的矛盾给出来源；常识/攻略需可核查依据；不确定时澄清，不虚构共同经历；评审连续反驳的干扰，频次上限待体验确定 |
| P20-09 | 主动了解授权范围内的用户行为，反馈频度与费用可控 | 采集、理解、开口是不同频率；低费用模式待答，15分钟尚未选定实现 |
| P20-10 | 安静模式不主动打扰，关闭观察后真正停止 | 用关闭/拒绝/退出及陈旧结果负例验证；收起聊天与关闭权限须区分 |

记忆是用户明确提出的最高优先级之一，应在完整主动陪伴之前验证其可行性。质量判断还包括多模态反馈的实时性和准确性、观察与回应能力、底层模型质量。先记录基线，再与用户确定可接受的延迟、误打断和召回目标，不用“像真人”“永不失忆”代替测量。

## 3. 记忆的产品含义

需要区分四件事：原始对话留存、重要事实的保存、在相关时刻准确想起、让生成模型正确使用。人格设定和用户画像分别维护，不能把角色说出的虚构故事写成用户事实。

称呼与明确确认的重要偏好需要稳定读取，不能只依赖语义检索的前几条结果。烦恼、共同经历等记忆要能回到原始消息及时间。明确纠正后保留当前有效事实，历史变化不能继续当现状使用。来源不充分时询问或承认不知道。

自动保存还是逐次确认仍待用户选择。无论选择哪种方式，都应有查看、纠正和删除入口。记忆候选方案先用同一组中文样本验证来源、变化、遗忘、隔离和重启；本轮没有选定 Mem0、MemOS 或图数据库。

## 4. 复用边界

- 桌面与界面：继承 AIRI `apps/stage-tamagotchi` 及真实消费闭包；聊天、设置、角色窗口保持原本业务职责。
- 人物与表现：先用 AIRI 示例验证；本轮实际渲染的是 Live2D 示例，不能把它写成 VRM 已实测。一个正式角色的人设、显示格式、动作及发行许可另行定稿。
- 对话和语音：先复用现有 Agent、provider、音频和表现链路。测出缺口后再确定局部增强或对照框架，不先整体替换。
- 记忆与主动陪伴：接入已有上下文/事件扩展点，权限、事实有效状态、删除和持久化由确定性代码维护。
- macOS、本地优先、无摄像头继续作为当前边界。用户说“看到诉求”目前按分享图片及授权看屏理解，未扩大为摄像头采集。
- 电脑自动操作、游戏代操作、云同步、订阅和自建角色继续后置；原版已有入口不等于自动纳入一期。
- 原版登录可能触发云会话/配置同步。本轮评估的登录路径不直接成为 Aimy 本地优先的产品方案。
- 旧 `apps/aimy-desktop` 及其自有会话/音频装配保留为历史样机；不整体导入新主线。必要修复按缺陷场景在原版接口重新适配，测试证据分别保留。

## 5. 按最新方向接续

| 顺序 | 用户能审阅的产物 | 进入实现或下一阶段的条件 |
|---|---|---|
| R0 已完成本轮范围 | 原版界面/真实文字对话、源码差距、GitHub 候选证据 | 本轮报告可读，未验项明确；不代表全部 AIRI 功能验收 |
| R1 原版成为主工程 | 固定原版来源，独立产品workspace，旧样机退出默认产品链路 | 原版桌面可运行，单一包/会话/音频主链路；来源和增量可追踪 |
| R2 Aimy品牌与界面定制 | 名称、图标、应用标识、品牌文字与必要外观，沿用原版流程 | 原版体验无回退；资料/服务归属和必要保护项清楚；用户能实际使用 |
| R3 实际使用与评审 | 用户走文字、图片、中文语音、角色和窗口场景 | 记录能力、自然度、延迟和失败，形成体验驱动的优化清单 |
| R4 按明确缺口优化 | 优先可靠记忆、自然语音/插话和人物反馈，再接主动陪伴/试用 | 每项先调查复用，提供对应真实体验与回归；不把改名当全部能力完成 |

这是用户最新方向对应的顺序，保留旧 A–E 及样机作为历史成果。下一步先准备主工程切换与品牌定制手册，再执行有界代码任务；当前没有启动源码搬迁、框架集成或大规模写代码。

## 6. 当前待答与待测

已提出的三个产品选择：

1. 收起聊天保留原版桌面角色，还是整个应用最小化后另留小角色？
2. 重要记忆自动保存，还是每次保存先确认？
3. 低费用模式是间隔看一眼，还是期间收集变化后定时汇总？也可暂留待定。

这三个选择约束对应的行为增强，不阻塞原版继承与初步品牌定制。

待测：真实麦克风/扬声器、ASR/TTS、回声与中文插话、图片理解、看屏及主动回应、30分钟稳定性、退出稳定性、正式资产/声音与安装分发。模型可由用户提供中国区服务；密钥只在后续受保护的本机配置中填写。
