# MiMo 语音密钥检测修复

日期：2026-10-18（Asia/Shanghai）。状态：已完成修复、隔离验证及体验包更新。
来源：用户反馈 MiMo 已填写 API Key，但测试按钮禁用并提示未填写，附设置截图。
用途：限定本次配置检测修复与验收。
风险：本地检测通过不代表供应商授权、余额或网络已通过。
替代关系：补充当前语音能力证据，保留此前检查原件。

## 范围与技术

- 仅修复 `aimy-app` 的 MiMo 语音合成设置页，不扩展语音识别或其他供应商。
- 保留现有加密存储、Provider 工厂和语音播放链，不新增依赖。
- 根因：密钥从普通配置移到加密存储后，页面仍以普通配置的 `apiKey` 判定是否填写。
- 复用 `resolveProviderConfig`，仅把“非空密钥存在”布尔值交给测试按钮。秘密不进入 Pinia 状态、localStorage 或日志。
- 跟随已提交配置变化重新检测。读取失败时禁用测试，不把存储失败当作供应商授权成功。
- 先用假密钥复现，再验证输入保存、页面重开、进程式状态重建、请求鉴权与存储故障。
- 所有请求使用模拟网络和假密钥。真实凭据、私人资料目录及付费请求不进入检查。
- 检查通过后更新已安装体验包，保留原应用身份、资料目录和之前的身体动作功能。旧包留备份。
- 不暂存、提交、推送，不修改其他批次功能。

## 验收

1. 修复前浏览器测试复现：秘密存储已有密钥，但测试按钮仍禁用。
2. 修复后假密钥保存、重开页面及重建状态后按钮可用，缺失或读取失败时禁用。
3. 模拟生成请求实际使用加密存储解析的密钥，响应走原音频链。没有真实网络请求。
4. 检查相关类型、浏览器回归、全仓要求和桌面构建，区分既有错误。
5. 包内隔离 profile 检查与安装包核对分别记录。真实账号连通与听感由用户测试。

## 检查后补充边界

浏览器复现确认保存和重开时按钮禁用。修复后四项行为断言通过，但存储故障暴露共享自动校验的未处理异常。
因此限定补充 `use-provider-validation.ts`：凭据读取失败时设为无效，使用现有校验失败文案并停止自动校验。
不把故障改成“未配置”而清除错误，不回显异常里的密钥或原始内容。
