### 1.2 B4 执行记录（2026-10-13）

素材来源：`docs/06-视觉设计/2026-10-13-AIRI交互风格库-v3/assets/aimy-icon-1024.png`（1024×1024，**无 alpha 通道**）。

因为源图是无 alpha 的 RGB 位图，不能直接编译成合法 macOS 图标，处理方式是套用 Apple 官方图标几何（1024 画布、824 圆角正方形主体、每边 100pt 内缩、圆角半径 ≈184）生成 alpha 遮罩，再降采样输出全部尺寸。

已装入 `aimy-app/apps/stage-tamagotchi/build/`：

| 文件 | 尺寸/槽位 | 说明 |
|---|---|---|
| `icon.png` | 1024 | 主图标 |
| `icon-512.png` | 512 | Linux/通用 |
| `icon.icns` | 10 槽位 | macOS 实际发布路径，已回环校验 |
| `icon.ico` | 6 尺寸（256/128/64/48/32/16） | Windows |
| `icons/icon.png` | 512 | **新建**，解决 `linux.icon: 'build/icons/icon.png'` 此前的悬空路径 |

本机无 Xcode 26，`hasXcode26OrAbove()` 返回假，`useIconFormattedMacAppIcon` 为假，因此 **`icon.icns` 是实际发货路径**，`build/icon.icon/` 在本机不可达。

`build/icon.icon/` 内仍是 AIRI 原始分层素材（`icon.json` 的 `fill-specializations` 未改），**待决定**：保留、替换或删除。本机不可达，暂不影响发布。

### 1.3 B4b 执行记录（2026-10-13）

`build/` 只影响打包产物。应用运行时的图标是另一套，位于 `apps/stage-tamagotchi/resources/`，此前仍是 AIRI 原图。本项补齐。

| 文件 | 尺寸 | 用途 | 引用点 |
|---|---|---|---|
| `icon.png` | 1024 | 全部窗口图标 + 托盘回退 | 15 个窗口模块 `src/main/windows/*/index.ts`、`src/main/tray/index.ts:24` |
| `icon-512.png` | 512 | 通用 | 无代码引用，保持成套 |
| `icon-dev.png` | 1024 | 开发模式 Dock 图标 | `src/main/index.ts:22`（仅 `is.dev`） |
| `tray-icon-macos.png` | 256 | macOS 托盘模板图 | `src/main/tray/index.ts:25` |
| `icon.svg` | 几何 | 几何源记录，不被代码引用 | — |

做法：

1. **应用图标**沿用 B4 的 Apple 几何（100pt 内缩，主体 824，圆角半径 ≈184）。三点与原图实测一致：原 `build/icon.png` 首个不透明像素在 y=100、x=100，末行 y=923，板外 alpha 为 0。
2. **不烘焙投影。** 实测原图板外像素 alpha 为 0，且 macOS 自行给应用图标加投影，烘焙会双重加影。
3. **窗口图标保持满幅。** 原 `resources/icon.png` 的四角是不透明的（即整幅方形咬合，无圆角留白），新图沿用，避免窗口图标出现胶片黑边。
4. **托盘改用设计库既有素材** `docs/06-视觉设计/2026-10-12-粉雾风格库/assets/aimy-tray-template.svg`（为小尺寸 `currentColor` 绘制），不新造标记。渲染为不透明黑 + 透明底，实测满足模板图契约：24,611 个不透明像素、40,925 个透明像素、**仅 1 种不透明颜色 `0,0,0`**，系统可自动适配深浅色菜单栏。
5. **DEV 标移到板内。** 原设计把角标画在画布角（x 874–1024, y 0–150），而该区域正落在板的圆角之外，被裁剪成空的。改为板内圆角胶囊并加白描边，标签完整可见。
6. `icon.svg` 从 base64 内嵌改为相对引用 `icon.png`（体积 966KB → 569B，且不会随素材更新而失同步）。

`hasAlpha: no` 的原始素材**未经直接使用**：`build/icon.png` 已是带上 alpha 遮罩的版本，用它作源可保证两套图标几何完全一致。

原始 AIRI 运行时图标当时备份至 `/tmp/aimy-icons2/backup-resources/`（临时目录，不保证仍存在）。回退须识别本批差异并保护用户已有资源修改，不执行覆盖目录的checkout/reset命令。

### 1.4 B1 执行记录与 userData 后果（2026-10-13）

`productName` 由 `AIRI` 改为 `Aimy`。配套事实：

- `artifactName`、`shortcutName`、`uninstallDisplayName` 均为 `${productName}` 模板，自动跟随，无需单改。
- 无任何代码分支依赖该字符串（已确认 `src/` 无 `app.getName()`／`productFilename`／`appName` 用法），故为纯配置改动。
- **userData 的行为要分开发与打包两种情况**，此前手册 §4 把两者混为一谈，此处更正：
  - **开发模式**：当前桌面命令为从aimy-app执行 `pnpm dev:tamagotchi`，通用 `pnpm dev`是Web。实际userData按运行模式及APP_USER_DATA_PATH核验，不仅凭productName推断；本轮不读取旧配置/密钥。
  - **打包产物**：旧记录曾发现同名Aimy资料目录已有旧样机数据，不能视为干净目录。开发/验收使用明确独立的合成profile，先核目录状态；不清空、迁移或自动读取旧运行资料。
- 目录改名不证明空配置或数据隔离，须按[当前环境入口](../00-当前方向/开发环境与工程位置.md)实际验证。

## 2. 明确不改（不做）

- **不改**内部包名 `@proj-airi/*`、IPC 通道名、IndexedDB 命名空间 `airi-local`、协议 `airi-sherpaw`——这些是内部约定，改名只会破坏功能且无用户可见收益。

- **不改**服务端地址、更新检查、遥测开关——本地优先边界在 R3 验收中单独核查，不在品牌轮改。
- **不删**任何 AIRI/Moeru AI 版权声明与 LICENSE 文件（MIT 上游要求保留）。
