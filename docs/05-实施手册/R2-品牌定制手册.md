## 2. 明确不改（不做）

- **不改**内部包名 `@proj-airi/*`、IPC 通道名、IndexedDB 命名空间 `airi-local`、协议 `airi-sherpaw`——这些是内部约定，改名只会破坏功能且无用户可见收益。
- **不改**窗口结构、页面布局、聊天流程、设置页面结构——UI 重设计等真实体验反馈（R3 之后）。
- **不改**服务端地址、更新检查、遥测开关——本地优先边界在 R3 验收中单独核查，不在品牌轮改。
- **不删**任何 AIRI/Moeru AI 版权声明与 LICENSE 文件（MIT 上游要求保留）。

## 3. 法律与署名

1. LICENSE 保留上游 MIT 全文；新增 `aimy-app/NOTICE`（或 THIRD_PARTY_NOTICES 追加）说明：Aimy 基于 [AIRI](https://github.com/moeru-ai/airi)（MIT）二次开发，原版权归 Moeru AI 及贡献者。
2. 图标、角色素材、音色是独立资产，许可单独核对（[资产清单](../03-技术与协作参考/资产清单.md)）；没有正式 Aimy 图标前，R2 可先沿用原图标发布内部版。
3. appId 待定项：若用户无自有域名，建议 `ai.aimy.desktop` 并在验收时确认不与既有应用冲突。

## 4. 执行方式

- 每个定制项一个独立 commit（B1–B8 分组提交），diff 可逐项审阅。
- 改动后运行 R1 的四项回归命令 + 启动应用截图对比，确认无回退。
- userData 目录变化意味着全新空配置启动——这是预期行为，原 AIRI 评估数据不迁移（本地优先，用户重新配置模型）。

## 6. UI 设计定位（本阶段）

R2 不做 UI 重设计。品牌表达限于：图标、名称、必要文案。原因：布局和交互以原版为起点（用户已明确），任何视觉方向调整应在真实使用（R3）后由体验驱动。届时利用 AIRI 自带 Chromatic 主题体系做增量调整，不另起 UI 框架。
