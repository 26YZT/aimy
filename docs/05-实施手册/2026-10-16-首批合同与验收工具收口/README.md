# 首批合同与验收工具收口

日期：2026-10-16，Asia/Shanghai。状态：接口与离线工具已实现、验证；付费执行入口仍待下一阶段。授权：用户“继续按计划开发”，承接已批准首批。目的：补齐剩余接口及原AIRI/Aimy同条件执行工具。唯一产品主工程仍为aimy-app；没有新增产品后端、向量库或主动聊天功能。

## 固定边界

- 记忆读取/回执沿现有Pinia owner、IndexedDB envelope和事实修订闭合；旧UI投影保留，不迁移旧资料。
- 两臂对照使用各自真实聊天store和原SDK形成的请求。AIRI记忆逻辑保持原版；只在受控临时构建增加共同测试时钟、费用/凭据传输和网络限制。
- 原来源和旧baseline只读。准备器用独立COW副本，机械重定位工具路径，记录适配与源码/依赖/产物指纹；不安装升级，不把本仓导入commit当上游commit。
- 场景时钟只进入消息时间、Aimy整理提示和相关召回；租约、保存回执、预算、超时与OS继续使用真实时间。
- Aimy继续现有安全Provider与费用gate；baseline SDK的fetch由仅验收的Eventa流式transport代理到测试host。该host复用既有BudgetLedger并在reserve/started后同步核当前run和取消，再单次发送。没有额外HTTP模型网关，也不重复给Aimy记账。
- baseline配置只含占位密钥。测试host从明确的专用验收vault取得授权并持有，Node/CDP runner不取得明文key；允许的endpoint、模型、模式和profile固定。真实凭据未配置或评测阶段未就绪时拒绝付费运行。
- 每个case/arm使用独立资料；case5真正退出后新PID读原会话；case7/8新空会话。预期/参考回答/禁项留grader侧，不能进入模型输入。

## 本轮实施责任

API worker：Memory DTO、profile/list/source/diagnostics、稳定写回执及UI重试。费用worker：可信Provider定义绑定、baseline fetch适配及共账本测试。构建worker：受控准备/构建和来源绑定。根：时钟、host/renderer测试桥、runner、诊断聚合、集成和最终证据。共享文件交还后再合并。

## 验证顺序

先以合成授权和本机固定响应跑完整18输入/臂的流程、持久化和费用闭环；结果明确标offline fixture，不记语义分数。接着复核输入隔离、请求次数、SSE、取消、未知usage、重启、源和产物、错误脱敏。真实模型阶段沿model-evaluation流程继续，已有模型/8例/一次¥10不重问，未冻结评分和未产生的真人判断不假报通过。

当前最早正式评测阶段仍需按已有目标卡/材料逐步审定；工程工具可先完成。本轮不会把工程批跑改名为真实模型验收，也不读取用户旧密钥来推进。
